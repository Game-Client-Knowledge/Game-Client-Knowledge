# C++11 新特性

## 1. 统一初始化（Uniform Initialization）

### 1.1 背景

C++03 中花括号 `{}` **只适用于 POD（平凡类型）**：数组和纯数据结构体。

```cpp
int arr[3] = {1, 2, 3};        // POD 数组可以用花括号
struct Point { int x, y; };
Point p = {1, 2};              // POD 聚合可以用花括号
std::vector<int> v;            // 非 POD 类不能用花括号
```

对非 POD 类型（带构造函数、私有成员等），要么不能用花括号，要么行为不一致。

### 1.2 C++11 的改进

花括号成为**统一语法**，对所有类型一视同仁：

```cpp
std::vector<int> v{1, 2, 3};          // 非 POD 类：花括号调用构造函数
std::string s{"hello"};
std::pair<int, int> p{1, 2};

int n{42};                            // 标量类型也可以
X x{};                                // 值初始化（零初始化）
```

- 聚合类型：花括号仍做成员列表初始化。
- 有构造函数的类：花括号直接调用构造函数，支持 `std::initializer_list`。
- **窄化转换被禁止**：`int n{2.5};` 编译报错，而 `int n = 2.5;` 静默截断。
- 规避最令人困惑的解析（most vexing parse）：`Foo f{};` 明确是对象构造，而不是 `Foo f();` 的函数声明。

## 2. 标准属性说明符（Standard Attributes）

### 2.1 背景

C++03 时代各家编译器各搞一套扩展：

```cpp
// GCC/Clang
__attribute__((noreturn))
// MSVC
__declspec(noreturn)
```

同一意图要写 `#ifdef` 分支，可移植性差。C++11 标准化了 `[[...]]` 语法。

### 2.2 标准属性一览

| 属性 | 标准 | 作用 |
|---|---|---|
| `[[noreturn]]` | C++11 | 声明函数永不返回，允许优化并消除告警 |
| `[[carries_dependency]]` | C++11 | 多线程依赖顺序优化 hint，极少使用 |
| `[[deprecated("...")]]` | C++14 | 标记废弃，使用产生编译告警 |
| `[[maybe_unused]]` | C++17 | 允许未使用，抑制告警 |
| `[[nodiscard]]` | C++17 | 返回值不可丢弃，丢弃产生告警 |
| `[[fallthrough]]` | C++17 | 声明 switch 穿透是有意的 |
| `[[likely]]` / `[[unlikely]]` | C++20 | 分支预测提示 |
| `[[no_unique_address]]` | C++20 | 空类成员不占用空间 |
| `[[assume]]` | C++23 | 声明条件恒为真，供优化使用 |

注意事项：

- 标准属性位置灵活，可用于类、函数、变量、参数、枚举等。
- 未知属性按规范应被忽略，保证向后兼容。
- 厂商扩展仍需 `[[gcc::...]]`、`[[msvc::...]]`、`[[clang::...]]` 前缀。

## 3. Lambda 表达式

### 3.1 本质：编译期生成的匿名闭包类

```cpp
auto f = [](int x) { return x * 2; };
f(21);
```

等价于编译器生成一个匿名类（闭包类）：

```cpp
class /* <lambda>，如 main::{lambda(int)#1} */ {
public:
    int operator()(int x) const { return x * 2; }
};
```

- **名字是编译器编造的**，源码无法写出，只能用 `auto`、`decltype` 或模板推导引用。
- 闭包类型定义在 lambda 表达式所在作用域，遵守局部类规则。
- 捕获的变量按值拷贝成闭包成员，或按引用绑定外层变量。
- **运行期零解析**：没有反射、没有动态查找，编译后就是一次直接函数调用（可内联）。

### 3.2 Lambda 与模板函数的区别

| 维度 | 普通 Lambda（C++11） | 模板函数 |
|---|---|---|
| 参数类型 | 固定写死 | 调用时推导/实例化 |
| 本质 | 匿名函数对象（具体类型） | 泛型代码模板 |
| 多种类型复用 | 不能 | 能 |

泛型能力由 C++14 的通用 Lambda 补齐，见 [03-cpp14](./03-cpp14.md)。

## 4. 函数类型擦除：std::function

### 4.1 原理：模板装箱 + 虚函数隐藏

```cpp
std::function<int(int)> f = [](int x) { return x * 2; };
```

展开结构：

```cpp
// 1. 内部基类：统一接口（纯虚）
struct _FuncBase {
    virtual int Call(int x) const = 0;
    virtual _FuncBase* Clone() const = 0;
    virtual ~_FuncBase() {}
};

// 2. 模板派生类：捕获具体类型
template <typename F>
struct _FuncImpl : _FuncBase {
    F fn;
    int Call(int x) const override { return fn(x); }
};

// 3. std::function 只持有 _FuncBase*（或小对象优化缓冲）
```

- **模板**负责编译期装箱：赋值瞬间为具体类型实例化 `_FuncImpl<F>`。
- **虚函数**负责运行期隐藏：对外只暴露统一接口。
- 赋值后具体对象身份被擦除，只保留调用协议。

### 4.2 擦除保留什么、擦除什么

| 保留 | 擦除 |
|---|---|
| 签名 `R(Args...)`，由模板参数写死，传错类型编译报错 | 具体可调用对象是谁（lambda 类型、函数指针目标） |

### 4.3 用途

| 场景 | 示例 |
|---|---|
| 回调/事件 | UI 按钮、定时器、异步完成通知 |
| 多线程 | 任务队列统一存储：`vector<std::function<void()>>` |
| 延迟执行 | 先注册、稍后统一调用 |
| 跨边界解耦 | 接口只约定签名，不暴露实现类型 |

### 4.4 成员函数指针的 this

```cpp
std::function<int(Obj&, int)> fn = &Obj::f;   // 第一个参数即显式 this
fn(obj, 42);

// 更常见：用 lambda 或 bind 把 this 提前焊死
std::function<int(int)> fn = [&obj](int x) { return obj.f(x); };
```

### 4.5 代价

- 每次调用一次虚函数跳转（约几 ns）。
- 内部可能堆分配，且 `std::function` 对象本体较大。
- 高频热路径优先用模板/lambda（零虚调用），`std::function` 用于需要统一存储的场景。

## 5. std::bind 与引用包装

### 5.1 bind 的实现原理

`std::bind` 生成一个**持有绑定参数 + 占位符的仿函数对象**：

```cpp
template <typename F, typename... BoundArgs>
class binder {
    F f;                               // 原类型存储，不是 std::function
    std::tuple<BoundArgs...> args;     // 绑定参数存进 tuple
public:
    template <typename... CallArgs>
    auto operator()(CallArgs&&... cargs) const {
        // 编译期展开：占位符换成调用参数，其余用绑定值
        return f(展开后的参数...);
    }
};
```

关键机制：

- **占位符识别**：`_1`、`_2` 是特殊空类型，`std::is_placeholder` 判断；占位符取调用参数对应位置，否则用绑定值。
- **参数重排**：`bind(f, _2, _1)` 可任意交换实参位置。
- **编译期展开**：`operator()` 编译后就是一次直接函数调用，无运行时解释、可内联。
- **按值存储**：绑定的是拷贝，引用必须显式用 `std::ref`。

```cpp
auto b = std::bind(f, 42, std::placeholders::_1);
b(99);   // 编译后等价于 f(42, 99)
```

### 5.2 std::ref 与 reference_wrapper

bind 默认按值拷贝：

```cpp
int x = 5;
auto b = std::bind(f, x);          // 拷贝 x，之后改 x 不影响 b
auto b2 = std::bind(f, std::ref(x));  // 引用绑定，改 x 同步生效
```

- `std::ref(x)` 返回 `std::reference_wrapper<int>`：内部存指针的可拷贝包装（引用本身不可拷贝）。
- 调用时隐式转回 `int&`。
- 与 lambda 的 `[&]` 捕获语义等价，只是 bind 需要显式包装。

### 5.3 bind 与 std::function、lambda 的关系

| 对象 | 类型 | 调用方式 | 用途 |
|---|---|---|---|
| `std::bind` 结果 | 模板生成的仿函数，`F` 保留原类型 | 直接调用，可内联 | 部分绑定、参数重排 |
| `std::function` | 类型擦除盒子 | 虚函数分派 | 统一存储、回调 |
| lambda | 匿名闭包类 | 直接调用 | 就地定义逻辑 |

三者可组合：`std::function<int(int)> fn = std::bind(&Obj::f, &o, _1);`

### 5.4 嵌套 bind/function 的调用栈问题

每层嵌套都是一次真实嵌套调用：

```cpp
std::function<void()> f1 = std::bind(work, _1);
std::function<void()> f2 = std::bind(f1, 42);
f2();   // 展开链：f2 -> f1 -> work，栈深线性叠加
```

- 涉及虚函数（`std::function` 必然虚分派）时难以内联折叠，嵌套 N 层就多 N 层栈帧。
- 缓解：优先 lambda 捕获而非层层 bind；用任务队列解耦长回调链，避免"回调套回调"。

# 内存分配器与分配器上下文

## 1. 为什么引擎要自定义分配器

系统 `malloc`/`free` 通用，但直接用于引擎高频路径有明显缺陷：

| 缺陷 | 说明 |
|---|---|
| 性能 | 元数据、锁竞争、空闲块查找，单次分配较慢 |
| 碎片化 | 长期随机分配/释放产生内存碎片，出现"总量够但分配不出连续大块" |
| 生命周期不匹配 | 帧内临时数据每帧分配/释放，通用分配器的开销被放大 |
| 不可观测 | 难以统计各系统占用、检测泄漏、控制对齐 |

不同场景需要不同分配策略：

| 分配器类型 | 特点 | 适用场景 |
|---|---|---|
| 线性/栈分配器 | 一次申请大块，指针移动分配，帧末重置 | 帧内临时数据，零释放成本 |
| 池分配器 | 固定对象大小，无碎片 | 同类小对象（实体、句柄、粒子） |
| Arena | 按批次生命周期整体回收 | 大量同生命周期对象（关卡加载） |
| malloc 封装 | 通用但慢 | 低频、大小随机的分配 |

## 2. 各策略要点

### 2.1 线性/栈分配器

```cpp
struct LinearAllocator {
    char*  base;
    size_t offset = 0;
    size_t capacity;

    void* alloc(size_t size, size_t align = 8) {
        offset = (offset + align - 1) & ~(align - 1);   // 向上对齐
        if (offset + size > capacity) return nullptr;
        void* p = base + offset;
        offset += size;
        return p;
    }

    void reset() { offset = 0; }   // 帧末整体重置
};
```

- 分配就是一次指针前移，释放即整体 reset，是**帧分配器**的标准实现。
- 不支持单个对象释放；跨帧存活的数据必须在 reset 前拷贝到长生命周期内存。

### 2.2 池分配器

- 预分配固定大小的块，空闲块串成链表：分配取表头，释放插回，无碎片、无搜索。
- 对象大小固定意味着要么浪费（对象小于块），要么按大小分级做多个池。

### 2.3 Arena

- 内部通常是线性分配并只记录总偏移；释放粒度是**整块 Arena**。
- 适合"一批对象同生共死"：关卡加载、单次导出、单帧提交。

## 3. 当前分配器与栈式上下文

引擎常用"当前分配器"模式：所有分配走全局当前上下文，进入某段代码时切换，离开时恢复。

```cpp
void PushAllocator(Context ctx) {
    ctx->prev = g_CurrentAllocator;
    g_CurrentAllocator = ctx;
}

void PopAllocator() {
    g_CurrentAllocator = g_CurrentAllocator->prev;
}
```

上下文是**栈式嵌套**的：外层用池分配器，某段临时操作切到线性分配器，结束后自动恢复。

### 3.1 为什么是"当前分配器 + Push/Pop"而不是写死

- **嵌套范围很自然**：某个系统整体用池分配器，其中一小段高频临时计算切到线性分配器，范围结束即恢复。
- **接口保持简单**：调用方只写 `New<T>()`，不关心当前是哪个分配器，也不需要在所有函数签名里传分配器参数。
- 代价是"当前分配器"属于全局（或线程级）状态：漏一次 Pop 会污染后续所有分配，因此切换必须配合守卫（见第 4 节）。

### 3.2 线程维度

- 当前分配器通常是**线程局部**的：每线程一份上下文栈，切换/恢复无锁。
- 跨线程分配与释放需要显式约定：谁分配谁释放、共享分配器加锁、或按线程分包。

## 4. AllocJanitor：分配器作用域守卫

```cpp
class AllocJanitor {
public:
    explicit AllocJanitor(mem::Context context) {
        mem::PushAllocator(context);
    }

    ~AllocJanitor() {
        mem::PopAllocator();
    }
};
```

- 无成员数据、无虚函数，是典型 mix-in 类（见 [C++98 基础](../cpp/01-cpp98.md)）。
- 构造切换、析构恢复，把"必然配对"交给语言机制（RAII），异常与提前返回都不会漏 Pop。
- 用法：

```cpp
{
    AllocJanitor janitor(frameCtx);
    buildMesh();     // 该作用域内的分配全部走帧分配器
}                    // 离开作用域自动恢复原分配器
```

## 5. 实践要点

| 要点 | 说明 |
|---|---|
| 对齐 | 分配接口提供对齐参数，SIMD/原子对象需要 16/64 字节对齐 |
| 统计与泄漏检测 | 在分配器层记录大小/调用栈/计数，导出内存报告 |
| 帧末检查 | 帧分配器 reset 前校验 offset 符合预期，尽早暴露"该释放却没释放" |
| 失败处理 | 明确分配失败的语义：返回 null、fallback 到下一级分配器还是直接崩溃 |

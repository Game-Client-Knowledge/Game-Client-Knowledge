# C++98 基础：继承、RAII、分配器与模板

## 1. 多重继承与 mix-in 类

### 1.1 结论

多数 C++ 开发者会**完全避免多重继承，或仅以受限形式使用**。常见经验法则是：

> 只允许简单的、没有父类的类被多重继承进一个严格单继承的层级结构中。这类类有时被称为 **mix-in（混入）类**。

### 1.2 为什么避免多重继承

| 问题 | 说明 |
|---|---|
| 菱形继承 | 同一基类经两条路径出现两次，派生类持有两份副本，语义和内存都膨胀 |
| 名字二义性 | 两个基类出现同名成员时，必须显式限定 `A::x` 或 `B::x` |
| 布局复杂 | 多基类子对象的偏移计算、向下转型成本上升 |
| 虚继承的代价 | 虚基类解决菱形问题，但引入间接层，布局与构造顺序更复杂 |

虚继承可以解决菱形继承，但通常被视作"更复杂"而不是"更正确"，所以团队规范往往直接禁止普通多重继承。

### 1.3 mix-in 类的特征

mix-in 之所以允许被多重继承，是因为它天然规避上述问题：

- **无状态或轻状态**：不携带数据，或只携带与宿主无关的少量状态。
- **不参与多态**：没有虚函数或虚函数极少，不会引入复杂的虚表合并。
- **只提供一项能力**：不表达"是什么"，只表达"能做到什么"。
- **可被任何类继承**：因为无共享基类，不会产生菱形或二义性。

典型示例：日志输出能力、序列化能力、RAII 守卫（见下一节）。

### 1.4 示例：AllocJanitor 是典型 mix-in

```cpp
class AllocJanitor {
public:
    explicit AllocJanitor(mem::Context context) {
        mem::PushAllocator(context);
    }

    ~AllocJanitor() {
        mem::PopAllocator();
    }
};
```

它无成员数据、无虚函数，只提供"进入作用域切换分配器、离开作用域恢复"这一项能力，可以被任何类以多重继承方式混入。

## 2. RAII 与作用域守卫

### 2.1 原理

RAII（Resource Acquisition Is Initialization，资源获取即初始化）：

- **构造函数获取资源**，**析构函数释放资源**。
- 利用 C++ 局部对象在作用域结束时**必定析构**的特性，保证资源一定释放。
- 即使中途抛出异常，栈展开也会调用析构函数，因此天然异常安全。

### 2.2 朴素写法与 RAII 对比

```cpp
// 朴素写法：手动配对，异常时漏掉 Pop
mem::PushAllocator(context);
doWork();                 // 若抛异常，这里漏执行 Pop
mem::PopAllocator();

// RAII 写法：析构必定执行
{
    AllocJanitor janitor(context);
    doWork();             // 无论正常返回还是抛异常，都会恢复分配器
}
```

### 2.3 适用场景

| 资源类型 | RAII 类示例 |
|---|---|
| 分配器上下文 | `AllocJanitor`（Push/Pop） |
| 互斥锁 | `std::lock_guard`（lock/unlock） |
| 文件句柄 | `std::fstream` |
| 动态内存 | 智能指针（`unique_ptr`/`shared_ptr`） |
| GPU 命令/作用域状态 | 自研守卫类 |

核心价值是**把"必然配对"的操作交给语言机制**，而不是依赖开发者记得成对书写。

## 3. 内存分配器

### 3.1 为什么要自定义多个分配器

系统 `malloc` 通用但有以下缺陷：

- **性能**：元数据、锁、内存池查找，单次分配较慢。
- **碎片化**：长期随机分配/释放产生内存碎片，出现"总量够但分配不出连续大块"。
- **生命周期不匹配**：帧内临时数据每帧分配/释放，开销被放大。
- **不可观测**：难以统计各系统占用、检测泄漏、控制对齐。

不同场景需要不同分配策略：

| 分配器类型 | 特点 | 适用场景 |
|---|---|---|
| 线性/栈分配器 | 一次申请大块，指针移动分配，帧末重置 | 帧内临时数据，零释放成本 |
| 池分配器 | 固定对象大小，无碎片 | 同类小对象（实体、句柄） |
| Arena | 按批次生命周期整体回收 | 大量同生命周期对象 |
| malloc 封装 | 通用但慢 | 低频、大小随机的分配 |

### 3.2 当前分配器与栈式上下文

引擎常用"当前分配器"模式：所有分配走全局当前上下文，进入某段代码时切换，离开时恢复。

```cpp
void PushAllocator(Context ctx) {
    ctx->prev = g_CurrentAllocator;
    g_CurrentAllocator = ctx;
}

void PopAllocator() {
    g_CurrentAllocator = g_CurrentAllocator->prev;
}
```

上下文是**栈式嵌套**的：外层用池分配器，某段临时操作切到线性分配器，结束后自动恢复。

### 3.3 为什么是"当前分配器 + Push/Pop"而不是写死

因为**嵌套范围很自然**：某个系统整体用池分配器，其中一小段高频临时计算切到线性分配器，范围结束即恢复。`AllocJanitor` 就是保证这个切换"必然配对"的守卫，这类无状态守卫类正是 mix-in 的典型用途。

## 4. 模板：特化与类型特征

### 4.1 为什么 numeric_limits 需要全特化

`std::numeric_limits<T>` 用**全特化**（每个具体类型一份）提供真实数值信息：

- 类型系统不表达 `int` 的范围、`double` 的 epsilon 等元数据，这些值由平台决定。
- 语言层面只提供 `sizeof`、`alignof`、类型特征等能力，没有"查询类型数值范围"的语法。
- 因此主模板给保守默认值，每个类型显式特化，标准库实现用编译器内置宏（如 `__INT_MAX__`）填充。

```cpp
template <typename T> class numeric_limits { /* 未知类型：保守默认值 */ };

template <> class numeric_limits<int>    { /* 真实值 */ };
template <> class numeric_limits<double> { /* 真实值 */ };
```

"编译器能不能自动算"：部分值可用元编程技巧计算（如无符号整型 `max = ~T(0)`），但不通用、不可靠，标准库选择显式特化保证编译期常量。

### 4.2 类型特征如何推导：is_pointer

机制是**主模板默认 false + 偏特化按形态匹配变 true**：

```cpp
// 主模板：兜底，默认不是指针
template <typename T> struct is_pointer : std::false_type {};

// 偏特化：匹配 "T*" 形态 -> true
template <typename T> struct is_pointer<T*> : std::true_type {};

// 指针自身带 const/volatile 的形态各写一份
template <typename T> struct is_pointer<T* const>          : std::true_type {};
template <typename T> struct is_pointer<T* volatile>       : std::true_type {};
template <typename T> struct is_pointer<T* const volatile> : std::true_type {};
```

匹配规则：

```text
is_pointer<int*>        -> T* 形态（T=int）       -> true
is_pointer<const int*>  -> T* 形态（T=const int） -> true
is_pointer<int* const>  -> T* const 那份           -> true
is_pointer<int>         -> 不匹配任何偏特化        -> false
is_pointer<int Obj::*>  -> 成员指针不是 T* 形态    -> false
```

- **成员指针**（`int Obj::*`）不算指针，由 `is_member_pointer` 覆盖——因为偏特化形态匹配不到。
- 现代标准库直接使用编译器内建 `__is_pointer(T)`，语义等价但编译更快、cv 组合处理更精确。
- 特化选择是**编译期纯模式匹配**，零运行时成本。

### 4.3 同类特征一览

| 特征 | 匹配形态 |
|---|---|
| `is_pointer<T>` | `T*`（及 cv 变体） |
| `is_reference<T>` | `T&`、`T&&` |
| `is_void<T>` | `void` 及 cv 变体 |
| `is_member_pointer<T>` | `T C::*` |
| `is_integral<T>` | 一组内置整型偏特化或编译器内建 |

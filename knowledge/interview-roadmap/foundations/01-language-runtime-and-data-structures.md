# 语言、运行时与数据结构

## 1. C++

C++ 是 Unreal、自研引擎、渲染和性能方向的核心语言。复习时应围绕“对象何时
出生、由谁拥有、存在哪里、何时销毁”组织知识，而不是把关键字当成集换式卡牌。

| 优先级 | 核心知识 |
|---|---|
| P0 | 指针与引用、`const`、栈与堆、对象生命周期、RAII |
| P0 | 构造/析构、拷贝/移动语义、左值/右值 |
| P0 | 虚函数、虚表、继承、多态、对象内存布局 |
| P0 | 智能指针、所有权、循环引用 |
| P0 | STL 容器、迭代器失效、时间复杂度 |
| P1 | 模板、泛型、SFINAE、C++20 Concepts |
| P1 | 内存对齐、placement new、自定义分配器 |
| P1 | 未定义行为、异常安全、ABI |
| P1 | 线程、锁、原子变量、内存序 |
| P2 | Cache-aware 容器、SIMD、无锁结构 |

典型问题：

- `struct` 和 `class` 的默认访问权限、默认继承方式有什么区别？
- 菱形继承会造成什么问题，虚继承如何解决？
- `vector` 扩容时发生什么，哪些引用和迭代器会失效？
- `map` 与 `unordered_map` 如何选择？
- `new` 与 `malloc` 在构造、失败处理和释放方式上有什么区别？
- `emplace_back` 是否一定比 `push_back` 更高效？
- `shared_ptr` 的控制块是什么，为什么会循环引用？
- 引用计数线程安全为什么不等于被管理对象线程安全？
- 虚函数调用为什么比直接调用多一层间接访问？
- 基类析构函数为什么通常应当是 `virtual`？
- `volatile` 为什么不能代替原子变量？

一个合格的回答示例：

> `vector` 是连续存储的动态数组。容量不足时会申请更大的连续空间，把旧元素
> 移动或拷贝过去并释放旧空间，因此指向旧元素的指针、引用和迭代器通常都会
> 失效。连续布局让遍历具有较好的局部性，但扩容不是免费搬家。

## 2. C#

C# 是 Unity 客户端的主要语言，重点是托管运行时、分配和引擎生命周期之间的
关系。

| 优先级 | 核心知识 |
|---|---|
| P0 | 值类型与引用类型、装箱与拆箱 |
| P0 | 类、接口、委托、事件、泛型 |
| P0 | GC、托管堆、分配与回收 |
| P0 | `List`、`Dictionary`、数组和枚举器 |
| P1 | 闭包、Lambda 捕获、反射、Attribute |
| P1 | 协程、Task、`async`/`await` 的差异 |
| P1 | Mono、IL、AOT、IL2CPP |
| P1 | Span、结构体复制、对象池 |
| P2 | Burst、Jobs、NativeContainer、安全句柄 |

典型问题：

- 值类型一定在栈上吗？
- 结构体赋给接口变量时为什么可能装箱？
- 哪些代码会产生 GC Alloc？
- C# GC 的分代机制和大对象堆如何影响游戏运行时？
- 事件订阅为什么可能造成内存泄漏？
- 委托和事件有什么区别？
- `List` 在无需保持顺序时如何低成本删除元素？
- Unity 协程是线程吗？
- IL2CPP 做了什么，为什么影响反射和泛型？
- 如何减少 `Update` 中的托管分配？

判断值类型位置时要看它属于谁：局部变量可能位于栈上，作为类字段时会跟随对象
位于托管堆中，装箱后也会进入堆。把“值类型在栈、引用类型在堆”背成铁律，
面试官只需追问一句就能让这条铁律变成薯条。

## 4. 通用数据结构与算法

| 优先级 | 核心知识 |
|---|---|
| P0 | 数组、链表、栈、队列、哈希表 |
| P0 | 二叉树、堆、排序、二分查找 |
| P0 | BFS、DFS、图的遍历 |
| P1 | LRU、并查集、Trie、跳表 |
| P1 | 拓扑排序、最短路径 |

典型问题：

- 为什么小规模数据线性扫描可能比哈希表更快？
- 哈希冲突有哪些处理方式？
- 快速排序如何降低最坏情况出现的概率？
- 如何判断链表有环并找到入环点？
- AVL 树和红黑树如何保持平衡？
- Top-K 如何用堆解决，复杂度是多少？
- DAG 如何进行拓扑排序和环检测？

复杂度描述增长趋势，硬件执行真实访问。小数组虽然是 O(n)，但内存连续、分支
简单；哈希表虽然平均 O(1)，却可能进行哈希计算和随机访存。大 O 不会骗人，
但它也不会替你查看 CPU Cache。

## 5. 游戏相关算法

| 优先级 | 核心知识 |
|---|---|
| P0 | A* 寻路、启发函数 |
| P1 | 四叉树、八叉树、BVH、空间哈希 |
| P1 | NavMesh 基本原理 |
| P1 | 有限状态机、行为树 |
| P2 | 流场寻路、群体行为、GOAP |

典型问题：

- A* 为什么能找到最短路径，启发函数有什么要求？
- 大量单位如何减少邻居查询成本？
- 四叉树、BVH 和空间哈希分别适合什么场景？
- NavMesh 遇到动态障碍物时如何更新或绕行？
- FSM 和行为树有什么差异？

以“查询玩家周围十米内的敌人”为例：

```text
直接扫描全部敌人
    优点：实现简单，小规模时可能最快
    缺点：敌人越多，每次查询越贵

空间哈希
    优点：动态对象更新简单，邻域查询快
    缺点：格子尺寸选择会影响效率

四叉树 / 八叉树
    优点：适合空间分布不均匀的数据
    缺点：频繁移动可能带来维护成本
```

面试回答不应只报出结构名称，还应说明对象数量、移动频率、空间维度和查询模式。

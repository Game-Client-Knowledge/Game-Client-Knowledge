# 游戏客户端八股分类

## 1. 优先级说明

本文使用以下优先级：

| 级别 | 含义 |
|---|---|
| P0 | 几乎所有游戏客户端岗位都应掌握 |
| P1 | 常见追问，取决于项目和引擎 |
| P2 | 专项岗位或中高级岗位重点 |

“八股”不应只背定义。每个知识点至少准备：

```text
定义
-> 底层原理
-> 常见方案对比
-> 适用场景
-> 项目中的真实例子
```

## 13. 项目经历与系统设计

这部分不是传统八股，但通常决定面试结果。

### 13.1 项目追问

必须准备：

```text
项目规模和个人职责
最复杂的模块
最严重的问题
定位过程
备选方案
最终选择
量化结果
失败或遗留问题
```

高频问题：

- 你负责的模块边界是什么？
- 最难定位的 Bug 是什么？
- 做过最有效的性能优化是什么，数据如何证明？
- 为什么选择当前架构，有哪些代价？
- 如果重新设计会改什么？
- 如何与服务端、策划、美术和测试协作？

### 13.2 系统设计题

常见题目：

- 设计技能和 Buff 系统。
- 设计背包、装备和道具系统。
- 设计任务与事件系统。
- 设计 UI 框架和页面生命周期。
- 设计资源加载和卸载系统。
- 设计对象池。
- 设计战斗状态同步。
- 设计大世界场景流式加载。
- 设计回放、录像或战斗复盘。
- 设计客户端日志和性能监控。

回答结构：

```text
目标与约束
-> 数据模型
-> 模块职责
-> 生命周期
-> 数据与控制流
-> 扩展性
-> 性能与并发
-> 异常和恢复
-> 测试与观测
```

## 15. 复习策略

### 第一阶段：建立主干

优先掌握：

```text
一门主语言
内存与并发
数据结构
游戏数学
引擎生命周期
资源管理
基础渲染

```

### 第二阶段：针对岗位

根据招聘描述选择 Unity、Unreal、渲染、网络或引擎专项，不要平均用力。

### 第三阶段：项目化回答

为每类知识准备一个项目案例：

```text
问题是什么
如何测量
为什么选择该方案
具体如何实现
结果如何
还存在哪些代价
```

### 第四阶段：模拟追问

对每个问题继续追问：

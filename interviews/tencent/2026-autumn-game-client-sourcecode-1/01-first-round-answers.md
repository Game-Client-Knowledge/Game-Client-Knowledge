## 2. 八股

### 2.1 C++ 的内存结构

常见回答可以从“进程虚拟地址空间”说起。一个 C++ 程序运行后，操作系统为进程提供独立的虚拟地址空间，典型区域包括：

- **代码段**：存放程序机器指令，通常只读、可执行。
- **只读数据段**：存放字符串字面量、`const` 全局常量等只读数据。
- **已初始化数据段**：存放已显式初始化的全局变量、静态变量。
- **BSS 段**：存放未显式初始化或零初始化的全局变量、静态变量，加载时置零。
- **堆**：动态分配区域，如 `new`、`malloc` 申请的内存，生命周期由程序控制。
- **栈**：函数调用栈，存放返回地址、栈帧、局部自动变量等，随函数调用和返回自动增长和回收。
- **内存映射区**：动态库、文件映射、匿名映射、大块分配等常放在这里。
- **线程局部存储 TLS**：存放 `thread_local` 对象，每个线程有独立副本。

面试中可以补一句：这是逻辑上的虚拟地址空间划分，不等于物理内存真实连续排列。虚拟地址会经过页表映射到物理页，操作系统可以做换页、权限控制和进程隔离。

从 C++ 对象角度看：

- 普通对象放在哪里取决于它的存储期和创建方式。
- 局部自动变量通常在栈上。
- `new` 出来的对象本体在堆上，但指针变量本身可能在栈上。
- 全局变量、静态局部变量、类静态成员通常在静态存储区。
- 带虚函数的对象通常额外包含 `vptr`，指向类的虚函数表。

### 2.2 智能指针和 `shared_ptr`

智能指针的核心作用是用 RAII 管理资源生命周期，让对象离开作用域时自动释放资源，减少裸指针泄漏和异常路径下忘记释放的问题。

常见智能指针：

- `std::unique_ptr<T>`：独占所有权，不能拷贝，可以移动，适合表达唯一拥有者。
- `std::shared_ptr<T>`：共享所有权，通过引用计数管理对象生命周期。
- `std::weak_ptr<T>`：弱引用，不增加强引用计数，用于观察 `shared_ptr` 管理的对象，也常用于打破循环引用。

`shared_ptr` 的基本机制：

```text
shared_ptr 对象
-> 指向被管理对象
-> 指向控制块 control block
-> 控制块保存强引用计数、弱引用计数、删除器、分配器等信息
```

当复制一个 `shared_ptr` 时，强引用计数加 1；当一个 `shared_ptr` 析构或重置时，强引用计数减 1。强引用计数变成 0 时，被管理对象被销毁。弱引用计数也变成 0 后，控制块才会释放。

面试追问点：

- `shared_ptr` 本身不是“所有操作都无锁”。引用计数增减通常是原子操作，但被指向对象的读写仍然需要额外同步。
- 不要用两个不同的 `shared_ptr` 分别接管同一个裸指针，否则会形成两个控制块，导致重复释放。
- 优先使用 `std::make_shared<T>()`，可以把对象和控制块合并分配，减少一次堆分配并提升局部性。
- 循环引用需要用 `weak_ptr` 打破。

示例：

```cpp
auto a = std::make_shared<int>(42);
auto b = a;              // 强引用计数增加
std::weak_ptr<int> w = a; // 弱引用，不延长 int 生命周期
```

### 2.3 `shared_ptr` 的引用计数存在什么位置

引用计数存在 `shared_ptr` 的控制块中，而不是通常意义上的被管理对象内部。

控制块一般包含：

```text
strong count：shared_ptr 数量
weak count：weak_ptr 数量以及控制块自身生命周期管理
deleter：对象销毁方式
allocator：控制块或对象的分配器信息
managed pointer：某些实现中保存被管理指针
```

两种常见创建方式有一点差异：

```cpp
auto p1 = std::shared_ptr<Foo>(new Foo());
auto p2 = std::make_shared<Foo>();
```

- `shared_ptr<Foo>(new Foo())` 通常会分别分配 `Foo` 对象和控制块。
- `make_shared<Foo>()` 通常会把控制块和 `Foo` 对象放在同一块内存里。

但无论哪种方式，引用计数的逻辑位置都是控制块。

### 2.4 局部静态变量的初始化和内存分配阶段

函数内的局部静态变量具有静态存储期，内存不是每次进入函数时在栈上重新分配，而是在程序的静态存储区域中分配。

可以按类型区分：

```cpp
void f() {
    static int a;          // 零初始化
    static int b = 10;     // 常量初始化
    static std::string s("hello"); // 动态初始化
}
```

- 内存分配：属于静态存储期，通常在程序装载时已经为其预留空间。
- 零初始化：程序启动阶段完成。
- 常量初始化：如果初始化表达式可在编译期确定，通常也在程序启动阶段完成。
- 动态初始化：函数第一次执行到该定义处时进行。

C++11 起，局部静态变量的初始化是线程安全的。多个线程同时第一次进入函数时，只有一个线程会执行初始化，其它线程等待初始化完成。初始化完成后，后续访问通常只需要很低成本的 guard 检查。

析构阶段：如果局部静态对象需要析构，一般在程序正常退出时析构，顺序与构造完成顺序相反。

### 2.5 `#define string char*` 与 `typedef char* string1`

题目：

```cpp
#define string char*

typedef char* string1;

string a, b;
string1 a1, b1;
```

宏是简单文本替换，所以：

```cpp
string a, b;
```

会被预处理成：

```cpp
char* a, b;
```

因此：

```text
a  的类型是 char*
b  的类型是 char
```

`typedef` 定义的是类型别名，所以：

```cpp
string1 a1, b1;
```

等价于：

```cpp
char* a1;
char* b1;
```

因此：

```text
a1 的类型是 char*
b1 的类型是 char*
```

面试中可以补充：这也是不推荐用宏做类型别名的原因。现代 C++ 更推荐 `using`：

```cpp
using string1 = char*;
```

另外，`char* a, b;` 中 `*` 是声明符的一部分，不是基本类型 `char*` 自动作用到所有变量。

### 2.6 单继承下有几个虚表指针和几个虚函数表

题目可以补成更接近 C++ 的写法：

```cpp
struct A {
    virtual void f1() {}
};

struct B : A {
    virtual void f2() {}
};
```

在常见 C++ ABI 实现中：

```text
A 对象：1 个虚表指针 vptr
B 对象：1 个虚表指针 vptr

A 类型：1 张虚函数表 vtable
B 类型：1 张虚函数表 vtable
```

所以如果问“`B` 的对象里有几个虚表指针”，答案通常是 **1 个**。如果问“程序里 `A` 和 `B` 一共有几张虚函数表”，答案通常是 **2 张**，分别对应 `A` 和 `B`。

原因是 `B` 是普通单继承，且基类 `A` 已经有虚函数。`B` 对象中会包含一个 `A` 子对象，那个子对象位置上有一个 `vptr`。构造 `B` 对象后，这个 `vptr` 最终指向 `B` 的虚函数表，而不是继续指向 `A` 的虚函数表。

可以抽象理解为：

```text
A object:
    [vptr -> A vtable]

B object:
    [A subobject vptr -> B vtable]
    [B's non-static data members...]
```

`B` 的虚函数表里通常会包含：

```text
A::f1 的槽位
B::f2 的槽位
```

如果 `B` 重写了 `f1`：

```cpp
struct B : A {
    void f1() override {}
    virtual void f2() {}
};
```

那么 `B` 的虚表中 `f1` 对应槽位会指向 `B::f1`，新增的 `f2` 会占用新的槽位。

面试中要注意限定语：

- C++ 标准没有规定必须用 `vptr/vtable` 实现，这是主流编译器的常见实现。
- 虚表通常按“多态类型”生成，不是每个对象一张表；对象里通常只存指向虚表的指针。
- 普通单继承一般只需要 1 个 `vptr`。
- 多继承时，如果有多个带虚函数的基类子对象，派生类对象里可能有多个 `vptr`。
- 虚继承场景还可能引入额外的虚基类偏移信息，布局会更复杂。

### 2.7 多线程中 `++` 为什么不加锁会导致数据不稳定

`++` 看起来是一条语句，但从 CPU 执行角度不是不可分割的原子操作。以共享变量 `x++` 为例，通常会拆成：

```text
从内存加载 x 到寄存器
寄存器中的值加 1
把结果写回内存
```

两个线程同时执行时可能发生：

```text
x 初始为 0

线程 A 读取 x = 0
线程 B 读取 x = 0
线程 A 计算 0 + 1 = 1
线程 B 计算 0 + 1 = 1
线程 A 写回 1
线程 B 写回 1
```

最终结果是 1，而不是期望的 2。这叫丢失更新。

从操作系统和硬件层面看，问题来自：

- 线程调度可能在读、改、写之间切换执行。
- 多核 CPU 每个核心有自己的寄存器和缓存层级。
- 普通读写没有自动提供互斥、原子性和顺序保证。
- 编译器和 CPU 可能在满足单线程语义的前提下重排指令。

解决方式：

```cpp
std::mutex m;
int x = 0;

void add() {
    std::lock_guard<std::mutex> lock(m);
    ++x;
}
```

或者使用原子类型：

```cpp
std::atomic<int> x{0};

void add() {
    x.fetch_add(1, std::memory_order_relaxed);
}
```

如果只需要计数最终正确，不依赖和其它变量的顺序关系，`memory_order_relaxed` 通常足够。如果要和其它内存状态建立同步关系，需要考虑 acquire-release 或默认的 sequentially consistent。

### 2.8 从主存读取的数据存到了哪

从主存读取的数据不会直接“只存在主存和变量里”。现代 CPU 访问内存通常经过多级缓存：

```text
主存
-> CPU cache line
-> L3 cache
-> L2 cache
-> L1 data cache
-> CPU 寄存器
```

实际路径和缓存层级取决于硬件架构。CPU 执行指令时，运算单元通常只能直接操作寄存器中的值，因此内存数据最终要加载到寄存器参与计算。

同时，缓存以 cache line 为单位加载，常见大小是 64 字节。读取一个 `int` 可能会把它所在的整条 cache line 拉入缓存。

### 2.9 读取需要 `++` 的变量时，数据最终放到了哪里

执行 `++x` 时，变量值最终会被加载到 CPU 寄存器中进行加法。

可以抽象成：

```asm
load  r1, [x]
add   r1, 1
store [x], r1
```

真实机器指令可能不同，也可能使用带内存操作数的指令，但微架构层面仍需要把值送入执行单元可处理的位置。

如果变量在缓存中命中，load 可能从 L1/L2/L3 cache 获取；如果缓存未命中，则需要从更低层缓存或主存加载。写回时也会先进入缓存体系，再按照缓存一致性协议与其它核心同步。

### 2.10 寄存器是每个线程独立的吗

从程序执行视角看，每个线程有自己独立的寄存器上下文，包括通用寄存器、栈指针、指令指针、部分状态寄存器等。

线程切换时，操作系统会保存当前线程的寄存器上下文，再恢复另一个线程的寄存器上下文。因此两个线程不会直接共享同一份逻辑寄存器值。

需要区分：

- **逻辑上下文**：每个线程独立，OS 负责保存和恢复。
- **物理寄存器资源**：同一个 CPU 核心上的物理寄存器会被不同线程在不同时间复用。
- **内存和缓存**：多个线程可以共享进程地址空间中的内存，因此共享变量仍会产生数据竞争。

所以，`x++` 的竞争不是因为线程共享寄存器，而是因为多个线程分别把同一个内存位置的旧值读到自己的寄存器中，各自计算后再写回同一个内存位置。

## 3. 算法

### 3.1 相邻元素相加为 10 则消除，求最终剩余数量

题意可以理解为：数组从左到右处理，如果当前元素和结果序列末尾元素相加为 10，则这两个元素消除；否则当前元素保留。因为消除后新的相邻元素可能继续形成可消除关系，所以适合用栈模拟。

示例：

```text
[1, 1, 9, 9]

push 1        -> [1]
push 1        -> [1, 1]
遇到 9，1+9=10 -> [1]
遇到 9，1+9=10 -> []

剩余数量 0
```

算法：

```cpp
#include <vector>

int remainingCount(const std::vector<int>& nums) {
    std::vector<int> st;
    st.reserve(nums.size());

    for (int value : nums) {
        if (!st.empty() && st.back() + value == 10) {
            st.pop_back();
        } else {
            st.push_back(value);
        }
    }

    return static_cast<int>(st.size());
}
```

复杂度：

```text
时间复杂度：O(n)，每个元素最多入栈一次、出栈一次
空间复杂度：O(n)，最坏情况下没有任何元素被消除
```

如果面试官追问“是否一定只消除当前相邻的一对”，可以说明：栈算法等价于持续维护已经处理前缀的最终结果。当前元素只可能和前缀最终结果的最后一个元素形成新的相邻关系，因此检查栈顶即可。

### 3.2 链表的倒数第 K 个值

经典双指针。先让 `fast` 指针向前走 `k` 步，然后 `fast` 和 `slow` 一起走。当 `fast` 到达链表末尾时，`slow` 正好指向倒数第 `k` 个节点。

需要先约定 `k` 从 1 开始：

```text
k = 1 表示倒数第一个，也就是尾节点
```

实现：

```cpp
#include <optional>

struct ListNode {
    int val = 0;
    ListNode* next = nullptr;
};

std::optional<int> kthFromEnd(ListNode* head, int k) {
    if (k <= 0) {
        return std::nullopt;
    }

    ListNode* fast = head;
    for (int i = 0; i < k; ++i) {
        if (fast == nullptr) {
            return std::nullopt;
        }
        fast = fast->next;
    }

    ListNode* slow = head;
    while (fast != nullptr) {
        fast = fast->next;
        slow = slow->next;
    }

    return slow == nullptr ? std::nullopt : std::optional<int>{slow->val};
}
```

复杂度：

```text
时间复杂度：O(n)
空间复杂度：O(1)
```

面试追问点：

- 如果 `k <= 0`，输入非法。
- 如果链表长度小于 `k`，返回空或按接口约定报错。
- 如果要求返回节点而不是值，把返回类型改成 `ListNode*` 即可。

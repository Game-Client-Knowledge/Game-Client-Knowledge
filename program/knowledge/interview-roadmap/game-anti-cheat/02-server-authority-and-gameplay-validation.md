# 服务器权威与玩法校验

## 第一原则：接受意图，不接受结果

不推荐：

```text
Client -> 我命中了玩家 B，造成 100 伤害
Server -> 直接扣血
```

推荐：

```text
Client -> Tick N 使用武器 W，方向 D，PredictionKey K
Server -> 验证身份、状态、射速、弹药和时间
-> 在权威世界执行判定
-> 生成伤害和结果事件
```

客户端可以预测动画、枪口和伤害数字，但服务器决定结果。

## 权威状态

服务器至少拥有：

- 玩家与实体身份、位置和生命周期；
- HP、Buff、技能、冷却和移动模式；
- 背包、货币、任务和掉落；
- 比赛 Tick、随机数和胜负；
- 可见性、队伍、权限和对象归属；
- 交易、结算和资产流水。

客户端缓存只是表现副本。断线重连时以服务器状态恢复。

## 通用校验层

每个请求依次检查：

1. **身份**：会话是否有效，账号和角色是否匹配？
2. **权限**：能否操作该实体、房间、物品或接口？
3. **时序**：Sequence/Tick 是否过旧、重复、跳跃或来自未来？
4. **状态**：当前状态机是否允许动作？
5. **资源**：弹药、法力、货币和次数是否足够？
6. **空间**：距离、速度、碰撞、视线和导航是否合理？
7. **频率**：射速、技能间隔、接口 QPS 是否超限？
8. **幂等**：相同业务请求是否已经完成？
9. **版本**：协议、配置和内容版本是否兼容？
10. **结果**：由服务器计算或在可验证边界内重建。

失败要返回稳定错误码并记录证据，不能把内部检测细节全部告诉客户端。

## 移动校验

服务器权威模拟是首选。若因规模使用较轻校验，至少考虑：

- 最大速度、加速度和转向速度；
- 固定 Tick 内可达位移；
- 地面、斜坡、跳跃、游泳和飞行状态；
- 碰撞、传送门、载具和移动平台；
- Buff/Debuff、负重和角色属性；
- 网络丢包与合法追帧；
- 服务器授权的 Teleport。

简单的“距离 / 时间 > 最大速度”会误伤传送、击退和平台运动。校验应基于服务器状态机和授权事件，而不是孤立阈值。

处理策略：

| 情况 | 处理 |
|---|---|
| 小误差 | 权威校正并累计风险 |
| 非法状态转移 | 拒绝动作并记录 |
| 持续异常 | 限制、隔离或进入复核 |
| 明确越权/伪造 | 阻断并提高风险等级 |

## 战斗校验

服务器检查：

- 武器/技能是否拥有并可用；
- 冷却、前后摇、资源和控制状态；
- 攻击频率和输入序列；
- 攻击者、目标和队伍关系；
- 距离、视线、碰撞和命中体；
- Lag Compensation 时间是否在可信窗口；
- 随机数、暴击、伤害和减免；
- 同一 Prediction Key 是否已处理。

客户端不能决定命中和伤害，但可以上报视角、输入 Tick 和目标提示，供服务器重建。

## 延迟补偿的安全边界

服务器回溯命中体不等于相信客户端时间：

1. 使用连接时钟估计将客户端 Tick 映射到服务器时间；
2. 限制最大回溯窗口；
3. 校验当时攻击者是否存活、持有武器并可开火；
4. 校验视角变化和射速；
5. 在历史查询场景执行命中检测；
6. 将结果应用到当前权威时间线。

异常时间戳、超窗口请求或重复开火直接拒绝或降级到当前时间判定。

## 帧同步与 Rollback

帧同步不等于服务器只做转发。服务器可以：

- 验证命令属于该玩家且当前可执行；
- 限制每 Tick 命令数量和参数；
- 统一排序、超时和缺失输入策略；
- 同时运行确定性权威模拟；
- 比对分层状态 Hash；
- 保存输入日志和检查点；
- 对隐藏信息只下发可见部分。

Rollback 项目同样可以由服务器中继、审计和结算。客户端回滚解决延迟，不授予最终权威。

## 经济与事务校验

资产操作使用服务端账本：

```text
RequestId / IdempotencyKey
-> 读取权威价格和库存
-> 校验余额、次数和活动版本
-> 原子扣减与发放
-> 写不可抵赖流水
-> 返回同一请求的稳定结果
```

不要信任客户端上报价格、折扣、奖励数量或支付成功。支付结果只接受可信支付渠道的服务端回调，并校验签名、订单和幂等。

## 隐藏信息最小化

服务器权威仍可能把全部敌人位置发给客户端，给透视留下数据源。应按业务限制：

- AOI、视野和遮挡；
- 战争迷雾；
- 隐藏牌、掉落和随机结果延后揭示；
- 观战延迟；
- 不向非拥有者发送私有 Buff、背包和技能选择；
- 日志与错误响应不泄露内部状态。

不下发比“下发后再防读取”更可靠。

## 限流与资源保护

分层限流：

- 连接级：包速率、字节数、无效包；
- 账号级：接口、角色、交易和匹配；
- 设备/IP/网段级：注册、登录和多开；
- 房间级：命令、聊天和对象生成；
- 全局级：依赖服务和昂贵查询。

只按 IP 限流会误伤 NAT 用户，也容易被代理绕过。组合身份、设备、会话和行为，并为正常突发留出 Token Bucket 容量。

## 失败与降级

校验服务或风控依赖不可用时要定义：

- 高风险经济操作失败关闭；
- 普通对局是否继续但加强日志；
- 客户端校验令牌过期是否允许短时续期；
- 模型超时是否回退到规则；
- 处置消息如何避免泄露检测规则；
- 如何快速关闭误伤规则。

防作弊不能成为让所有正常玩家无法登录的单点故障。

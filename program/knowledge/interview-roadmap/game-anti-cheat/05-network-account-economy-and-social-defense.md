# 协议、账号、经济与社交防护

## 协议防护目标

网络安全主要保证：

- 消息来自已认证会话；
- 传输内容未被中途篡改；
- 旧消息不能无限重放；
- 请求只能操作有权限的对象；
- 重复、乱序和并发不会产生额外收益；
- 恶意流量不能拖垮房间或后端。

加密保护链路，不验证玩法合法性。一个经过正确加密的“非法购买请求”仍然非法。

## 会话与消息

通用措施：

- TLS、DTLS、QUIC 或经过审计的认证加密协议；
- 短期会话令牌与安全刷新；
- Packet Sequence、Nonce 和重放窗口；
- 消息绑定 Connection/Session/Match；
- 关键业务请求使用 Idempotency Key；
- 服务端验证消息类型、长度、数量和枚举；
- 拒绝旧协议、撤销会话和异常版本；
- 密钥轮换，不自创未经审计的密码算法。

不要把客户端内置的静态秘密当成永久服务器凭据。

## 重放与重复请求

对局输入可按 Tick/Sequence 去重；经济请求按业务 ID 幂等：

```text
IdempotencyKey -> 查询已有结果
-> 未处理：执行事务并保存结果
-> 已处理：返回原结果，不再扣款或发奖
```

只在客户端禁用按钮无法防止重复提交。服务器还要处理网络重试、并发请求、服务重启和消息队列重复投递。

## 越权与对象归属

每次请求验证：

- 当前账号/角色是否拥有对象；
- 是否属于同一房间、队伍和服务器；
- 是否能看到或操作目标；
- 当前状态是否允许接口；
- 目标 ID 是否仍是同一 generation；
- 管理接口是否只对内部身份开放。

“客户端 UI 没有这个按钮”不是权限控制。

## 账号安全

常见风险：

- 撞库、弱密码和凭据填充；
- 钓鱼、恶意插件和会话窃取；
- 账号交易、共享和代练；
- 批量注册和养号；
- 设备更换后盗号转移资产。

防御：

- 密码安全存储、登录限流和泄漏密码检查；
- MFA/无密码登录等增强认证；
- 新设备、异地和异常 ASN 风险评估；
- 高价值操作二次验证与冷静期；
- 会话管理、远程登出和令牌撤销；
- 账号恢复流程防社会工程；
- 登录、设备和资产操作审计。

IP 地址会共享和变化，设备指纹也可能漂移或被伪造，只能作为组合信号。

## 设备、模拟器与多开

设备维度可用于：

- 限制批量注册和活动滥用；
- 识别同设备账号群；
- 高风险环境附加验证；
- 关联封禁规避和资源转移。

风险：

- 家庭、网吧、云游戏和共享设备；
- 硬件升级与系统重装；
- 隐私法规与平台政策；
- 指纹碰撞和伪造；
- 模拟器的合法测试与无障碍用途。

合理策略是风险分层，不是“一台设备只能一个账号”的绝对规则。

## 经济账本

线上资产应使用服务器权威账本：

| 要求 | 含义 |
|---|---|
| 原子性 | 扣减与发放要么都成功，要么都失败 |
| 幂等 | 重试不会重复产生资产 |
| 可追踪 | 每次变化有来源、去向、版本和业务 ID |
| 守恒 | 非系统产出场景中总量变化可解释 |
| 可回溯 | 能重建异常资产流向 |
| 可冻结 | 高风险资产可限制交易而不立即销毁证据 |

异常检测关注：

- 产出/消耗偏离；
- 短时间跨账号汇聚；
- 新账号快速达到高价值；
- 交易价格与市场偏离；
- 封禁账号的关联转移；
- 支付、退款与资产发放不一致。

## 支付与订单

- 订单由服务器生成并绑定账号、商品、金额和币种；
- 客户端支付成功页面不是最终凭证；
- 只接受支付渠道服务端回调；
- 验证签名、订单状态、金额和幂等；
- 退款/拒付与资产回收有明确策略；
- 测试环境和正式环境密钥隔离；
- 客服补发同样进入审计账本。

防作弊也要保护内部运营和客服工具，避免高权限接口成为资产入口。

## 交易与工作室

单账号规则很难发现工作室。关系图可包含：

```text
Account -- Device / IP / Payment / Trade / Party / Match -- Account
```

关注：

- 大量源账号向少数中转/收款账号汇聚；
- 新账号按模板成长后转移资产；
- 固定队伍和交易链重复出现；
- 被处置节点周围快速生成替代节点；
- 资源产出与正常玩法时间不匹配。

处置可分层：限制交易、延迟到账、冻结高风险资产、提高验证、隔离匹配，再根据证据封禁和追缴。

## 竞技操纵

常见形式：

- 演员和故意送分；
- 胜负交易与互刷；
- Boosting/代练；
- Smurf/炸鱼；
- 组队规避匹配；
- 观战或直播窥屏。

检测信号：

- 对手/队友重复关系；
- 异常投降、送分和行为变化；
- 段位提升与设备/地区突变；
- 账号间登录和组队关系；
- 关键对局回放与举报；
- 收益、时间和社交图的一致性。

Smurf 与作弊并非完全相同，治理目标可能是匹配质量而非永久封禁。

## 服务滥用

防止：

- 登录/匹配/聊天洪泛；
- 创建大量房间或实体；
- 发送超大、压缩异常或高成本查询；
- 利用错误路径制造日志风暴；
- 对单局目标持续骚扰。

措施包括限流、配额、成本预算、超时、熔断、隔离队列和 DDoS 防护。解析网络数据前先限制长度和复杂度。

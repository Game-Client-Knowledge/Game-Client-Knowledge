# 游戏客户端面试复习路线

## 使用方式

本模块面向已有语言和引擎经验、正在进行面试复习的客户端开发。它不是从零教材，而是一张按岗位裁剪的复习网络。

每个主题只检查五件事：

```text
一句话结论 -> 关键数据/控制流 -> 方案对比
-> 失效边界 -> 项目工具、指标与结果
```

定义说完后没有机制与证据，通常只能应付第一层追问。

## 岗位路线

- **Unity 玩法**：C# / 数据结构 → PlayerLoop / 生命周期 → 资源与异步 → 物理/渲染概览 → 多人游戏 → Profiler 与项目题。
- **UE 玩法**：C++ / UObject → Gameplay Framework → 资源与 Replication → 多人游戏 → Blueprint 边界 → Insights / 构建 → 项目题。
- **自研引擎**：C++ / 内存并发 → 主循环 / Job System → 资源管线 → 数学与渲染 → 跨平台与性能。
- **渲染**：C++ / Cache → 线性代数 → CPU 提交 → GPU 流水线 → Shader / 现代管线 → GPU Capture。

## 时间预算

| 时间 | 做法 |
|---|---|
| 1 天 | 知识地图选 P0；每项录一段 60 秒回答 |
| 3 天 | 补引擎专项；做综合模拟题；整理两个项目案例 |
| 1 周 | 完整专项、真题模拟、追问树和薄弱点回炉 |

复习进度按“能否脱稿输出”计算，不按“是否看过”计算。

## 回答模板

```text
结论：我选择什么
流程：数据由谁产生、在哪个线程、何时被消费
取舍：为什么不是备选方案
风险：生命周期、并发、性能、确定性、兼容性
验证：设备/场景、工具、基线、结果、回归
```

## 项目证据清单

至少准备：

1. 一个性能案例：基线、Profiler 证据、改动、收益和副作用；
2. 一个稳定性案例：崩溃/泄漏/竞态的根因与防回归；
3. 一个系统设计：规模约束、数据流、失败处理与演进；
4. 一个失败决策：原方案为何失效，怎样修正判断。

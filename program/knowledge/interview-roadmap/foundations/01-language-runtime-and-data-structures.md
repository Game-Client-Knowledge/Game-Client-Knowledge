# 语言、运行时与数据结构速记

## C++

| 主题 | 回答抓手 |
|---|---|
| 生命周期 | RAII 将资源绑定对象；构造成功的子对象逆序析构；虚基类需虚析构 |
| 所有权 | `unique_ptr` 单一所有权，`shared_ptr` 有控制块/原子成本并可能成环，`weak_ptr` 观察 |
| 移动 | 转移资源，不保证“零成本”；moved-from 对象有效但值通常未指定 |
| 多态 | 虚调用经 vptr/vtable 动态分派；有间接访问、布局和优化影响 |
| 模板 | 编译期多态与代码膨胀/编译时间权衡；concept 可约束接口 |
| UB | 越界、悬空、数据竞争等会破坏任何表面推理，不能靠“本机能跑”证明正确 |

追问准备：对象布局、对齐、复制/移动规则、异常安全、allocator、容器失效、原子内存序。

## C# / Unity 运行时

- 引用类型通常在托管堆，值类型位置取决于上下文；装箱会创建对象。
- GC 回收不可达托管对象，不自动解决事件订阅、原生资源和 Unity 对象生命周期。
- `IDisposable/using` 管确定性资源；finalizer 只作兜底。
- delegate/closure、LINQ、字符串和临时集合是常见每帧分配源。
- Mono 与 IL2CPP 在 JIT/AOT、反射、泛型、裁剪和调试上不同；编辑器结果不能代替真机发布包。
- Unity `Object` 可能托管 wrapper 仍在而原生对象已销毁，产生 fake-null 语义。

## 通用数据结构

| 需求 | 首选思路 | 常见追问 |
|---|---|---|
| 连续遍历/随机访问 | vector/array | 扩容、失效、Cache、尾插摊还 |
| 稳定节点/频繁中间插删 | list（先证明需要） | 节点分配和局部性往往更差 |
| Key 查找 | hash / ordered tree | 碰撞、rehash、顺序、最坏复杂度 |
| FIFO/任务队列 | ring buffer/deque | 满空判断、并发模型、背压 |
| 优先任务 | heap/priority queue | 更新优先级、稳定性 |
| 稀疏关系 | graph | 邻接表/矩阵、遍历与内存规模 |

Big-O 相同不代表性能相同。客户端回答要补充连续布局、分支、预取、分配次数和数据规模。

## 游戏相关算法

- **A***：`f=g+h`；可采纳启发保证最优，开放/关闭集与寻路网格决定成本。
- **空间索引**：Quadtree/Octree/BVH/Grid 取决于维度、动态程度、分布和查询类型。
- **LRU**：Hash + 双向链表实现 O(1)；资源缓存还需容量按字节、引用、异步与淘汰安全点。
- **对象池**：减少分配但会延长引用、抬高常驻内存；必须重置状态和验证实际收益。
- **ECS**：组件连续存储提高批处理与 Cache；结构变更、随机访问和系统依赖是代价。

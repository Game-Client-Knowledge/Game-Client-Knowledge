# 系统、网络与游戏数学

## 1. 内存体系

| 优先级 | 核心知识 |
|---|---|
| P0 | 栈、堆、虚拟内存、分页 |
| P0 | CPU Cache、Cache Line、局部性 |
| P0 | 内存碎片、对象池、内存池 |
| P1 | 对齐、Padding、SoA 与 AoS |
| P1 | False Sharing、NUMA 基础 |

典型问题：

- 顺序数组为什么通常比链表遍历快？
- CPU Cache Miss 为什么会造成停顿？
- 内存池如何减少碎片和分配开销？
- AoS 和 SoA 如何选择？
- 虚拟地址如何转换为物理地址？
- 函数调用栈通常保存哪些信息？
- 进程崩溃和线程崩溃的影响范围有何区别？

可以把内存层级想成厨房取料：

```text
寄存器：手里正拿着的调料
L1/L2/L3 Cache：灶台和附近架子
主内存：后厨仓库
磁盘：开车去批发市场
```

算法只写“取一勺盐”，性能却取决于盐在哪。连续访问让硬件更容易提前把下一批
数据搬到附近，这就是局部性在工程中的价值。

## 2. 线程与同步

| 优先级 | 核心知识 |
|---|---|
| P0 | 进程、线程、协程 |
| P0 | 互斥锁、读写锁、信号量、条件变量 |
| P0 | 死锁条件和避免方式 |
| P1 | 原子操作、CAS、内存可见性 |
| P1 | 线程池、Job System、工作窃取 |
| P2 | 无锁队列、内存序、RCU |

典型问题：

- 线程和协程有什么区别？
- 自旋锁与互斥锁如何选择？
- 什么是 False Sharing？
- 多线程任务系统为什么需要工作窃取？
- 原子操作为什么仍需考虑内存序？
- 系统调用为何会有额外开销？
- 如何通过锁顺序、超时或资源分级避免死锁？

多线程优化的目标不是“让所有核看起来都很忙”，而是缩短关键路径：

```text
拆任务 -> 建立依赖 -> 并行执行 -> 在必要位置同步
```

任务过小会被调度成本吞掉，任务过大又无法均衡；同步点过多时，八个线程可能
只是排成一支比单线程更有仪式感的队伍。

本节完成后可使用[操作系统、内存与并发综合模拟题](../02-os-memory-concurrency-mock-interview.md)
进行完整演练。

## 3. 计算机网络

这里讨论通用传输基础，游戏状态同步在
[引擎与客户端核心](../engine-client/02-physics-animation-network-and-platforms.md)
中展开。

| 优先级 | 核心知识 |
|---|---|
| P0 | TCP 与 UDP 的差异 |
| P0 | TCP 建连、断连、重传、滑动窗口 |
| P0 | 延迟、抖动、丢包、带宽 |
| P1 | 粘包与拆包、消息边界 |
| P1 | 心跳、断线重连、超时 |
| P1 | HTTP、WebSocket、TLS 基础 |
| P1 | 序列化、压缩、大小端 |
| P2 | 在 UDP 上实现可靠传输 |

典型问题：

- TCP 为什么可靠，又为什么可能不适合强实时数据？
- UDP 为什么不会天然更快？
- 三次握手和四次挥手分别解决什么问题？
- 如何在 UDP 上实现序列号、确认和超时重传？
- 如何设计消息包头和消息边界？
- 如何处理弱网、乱序、重复包和断线重连？

选择协议时应先看业务语义：

| 数据 | 更关注什么 | 常见处理 |
|---|---|---|
| 登录、付费结果 | 必须可靠且有顺序 | TCP/HTTPS |
| 聊天消息 | 可靠、延迟要求一般 | TCP/WebSocket |
| 高频位置快照 | 新数据通常比旧数据重要 | UDP 或定制传输 |
| 玩家输入 | 低延迟且常需部分可靠 | UDP + 序号/确认 |

典型问题：

- 点积如何判断夹角和前后关系？
- 叉积如何判断左右和求法线？
- 四元数为什么适合表示旋转？

三个最常用的直觉：

```text

叉积：两个方向共同撑起的平面的法线
矩阵：把一个坐标系中的描述转换到另一个坐标系
```

[坐标空间与 CPU 准备](../rendering/02-coordinate-spaces-and-cpu-preparation.md)
中结合流水线继续讲解。

## 5. 几何基础

| 优先级 | 核心知识 |
|---|---|
| P0 | 点到线/平面距离 |
| P0 | 射线与平面、AABB 相交 |
| P1 | AABB、OBB、包围球 |
| P1 | 重心坐标、射线三角形检测 |
| P2 | SAT、GJK 的数学基础 |

典型问题：

- 如何判断点是否在三角形内？
- 如何实现射线与三角形相交？
- AABB 和 OBB 的精度与更新成本有何差异？
- 为什么碰撞检测通常分为粗检测和精检测？

几何检测常采用“便宜的测试先挡门，昂贵的测试后验票”：

```text
包围球 / AABB 粗筛
-> OBB 或凸体进一步判断
-> 必要时进行三角形级精确检测
```

这和机场安检的思路相似：不会让每位旅客一进门就接受发动机拆解级检查。

# 引擎架构与运行时速记

## 主循环与时间

典型帧包含输入/网络、固定步仿真、逻辑、动画、渲染提取与提交。关键区分：

- 变量步长适合表现更新，但结果受帧率影响；
- 固定步长提高物理/确定性稳定性，但卡顿后追帧可能形成死亡螺旋；
- accumulator + 最大追帧次数控制债务，渲染可在仿真快照间插值；
- 暂停、time scale、后台切换和网络时钟必须分别定义。

Tick/Update 不是免费。静态对象使用事件，批量对象使用 System，异步工作用任务与完成消息。

## 对象与模块

| 组织方式 | 适合 | 代价 |
|---|---|---|
| 继承层级 | 稳定 is-a 与共享实现 | 耦合、脆弱基类、布局限制 |
| Component | 按能力组合对象 | 组件通信与生命周期 |
| ECS | 批量同构数据处理 | 结构变更、随机访问、调度复杂度 |
| Service/Subsystem | 全局或世界级能力 | 容易变成万能单例 |
| Event/Message | 解耦通知和跨线程结果 | 隐式依赖、顺序、重入、泄漏 |

模块边界应由依赖方向和生命周期决定；全局 Service Locator 会隐藏真实依赖。事件发布事实，命令请求动作，查询返回数据。

## 资源生命周期

```text
逻辑标识 -> 依赖解析 -> IO -> 解压/反序列化
-> GPU/引擎对象创建 -> 引用/实例 -> 释放与缓存淘汰
```

异步读取不等于无主线程尖峰：实例化、上传、Shader 编译和对象注册仍可能卡帧。资源系统需处理：

- 强/软引用与依赖图；
- 去重、优先级、取消和晚到结果；
- handle + generation 或版本，防止旧回调操作新对象；
- 引用计数、缓存预算、LRU 与场景卸载安全点；
- 包版本、哈希、回滚和加载指标。

## 场景与世界流送

场景切换不只是加载文件：要冻结输入、保存状态、取消旧任务、卸载对象、加载依赖、分帧实例化、激活新世界并恢复网络/表现。

大世界通过空间分块、可见性、HLOD 和流送源控制工作集。跨分块硬引用会破坏卸载；持久实体与关卡实体应分属清晰所有者。

## 多线程流水

worker 只处理声明的数据快照或独占分区，结果通过命令缓冲汇合。Game/Render 线程常并行处理不同帧，任何强制 flush、同步资源创建和读回都可能打断流水。

回答 Job System 时说明任务粒度、读写集、DAG、work stealing、主线程等待点、结构变更与取消协议。

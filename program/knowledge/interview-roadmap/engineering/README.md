# 工程实践与项目表达

## 目标

知识题确认理解，工程题确认能否把系统做稳，项目追问确认是否真正做过。所有回答都应形成闭环：

```text
现象 -> 指标/基线 -> 工具证据 -> 可证伪假设
-> 最小改动 -> 前后对比 -> 副作用 -> 回归与监控
```

## 内容

1. [性能优化与工程化](./01-performance-and-production.md)：CPU/GPU/内存/资源/稳定性分析。
2. [项目表达与复习策略](./02-project-design-and-study-strategy.md)：项目追问、系统设计和复盘。

## 最低证据

- 明确设备、构建、场景和数据规模；
- 给优化前基线与关键 trace/capture；
- 说明为什么选择该改动而非备选；
- 给结果、代价和回归方式；
- 不能披露业务数值时，至少提供百分比、数量级和方法。

“感觉更流畅”不是性能指标，“线上没再出现”也不是完整稳定性证明。

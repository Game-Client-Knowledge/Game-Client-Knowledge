# 性能优化与工程化速记

## 瓶颈分类

先看帧时间而非 FPS，并区分平均、P95/P99 与长尾。

| 类别 | 证据 | 常见方向 |
|---|---|---|
| Main/Game Thread | 长任务、脚本、GC、同步加载 | 事件/批处理、分帧、生命周期治理 |
| Worker | 排队、等待、负载不均 | 任务粒度、依赖图、数据分区 |
| Render Thread | Draw/状态切换、命令构建 | 批处理、实例化、裁剪、材质治理 |
| GPU | Pass、带宽、像素/几何瓶颈 | 分辨率、Overdraw、Shader、LOD |
| 内存/IO | 峰值、抖动、page fault、加载 | 生命周期、压缩、预取、流送 |
| 网络 | RTT/jitter/loss/队列 | 协议、预测、压缩、重试/背压 |

CPU/GPU 可能流水并行；单看一侧总时间会误判。用 profiler timeline、GPU capture、硬件计数器和平台工具交叉验证。

## CPU 与内存

优先处理算法/工作量、边界调用、数据布局和分配，再做局部微优化。关注：

- 每帧对象数、分配速率、GC/allocator 峰值；
- Cache miss、false sharing、内存带宽；
- 主线程等待与 worker 拖尾；
- 锁竞争、文件/网络阻塞与日志；
- 泄漏、池保留、缓存预算和碎片的区别。

## GPU

先用 capture 确认瓶颈属于几何、像素、带宽、同步还是 CPU 提交。常见抓手：

- 可见性、LOD、实例化与 Draw Call；
- 分辨率、透明 Overdraw、后处理和阴影；
- Shader 指令、分支、纹理采样与 variant；
- Render Target 格式/带宽、MSAA 和移动端 tile store；
- CPU-GPU sync、readback 与资源上传。

降低 Draw Call 不保证 GPU 更快，合批可能增加顶点、内存或剔除粒度。

## 资源与稳定性

加载链要分 IO、解压、反序列化、依赖、实例化、上传和激活。按阶段记录耗时与峰值，避免把所有尖峰归为“磁盘慢”。

稳定性需要崩溃符号、版本/设备/场景、面包屑、OOM 指标和自动聚类。修复后补单测、回放、压力或真机自动化，避免只靠人工确认。

## 标准优化闭环

1. 固定设备、发布构建、场景和输入；
2. 建立帧/内存/温度/网络基线；
3. 用 trace/capture 定位最大账目；
4. 提出一个可证伪假设；
5. 修改一个关键变量；
6. 比较 P50/P95/P99、峰值与质量；
7. 回归正确性、画质、功耗和弱设备；
8. 将预算、告警和自动场景加入 CI/监控。

## 高频追问

1. CPU bound 与 GPU bound 如何判定？
2. 为什么平均 60 FPS 仍然卡？
3. 合批、对象池、异步加载分别可能带来什么反作用？
4. 内存峰值下降但 RSS 不降，如何解释？
5. 移动端发热后掉帧如何验证 thermal throttling？
6. 优化结果如何防止后续版本回退？

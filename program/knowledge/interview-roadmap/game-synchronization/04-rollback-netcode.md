# Rollback Netcode

## 核心结论

Rollback 同样主要同步输入，但不等待所有远端输入到齐。客户端对缺失输入做预测，立即推进确定性模拟；真实输入晚到且与预测不同时，恢复历史状态并重模拟。

```text
预测远端 Tick K 输入 -> 立即执行到当前 Tick N
真实 Tick K 输入到达
-> 若预测正确：继续
-> 若预测错误：恢复 K-1 快照
-> 用真实输入重放 K..N
-> 平滑表现误差
```

它用额外 CPU、历史内存和实现复杂度换取更低的输入延迟。

## 同步什么

网络主要携带：

```text
InputPacket {
  playerId
  newestInputTick
  ackedRemoteTick
  recentInputs[]   // 常冗余多个 Tick
  stateHash?
}
```

还可能携带：

- Match 初始状态和随机种子；
- 已确认 Tick；
- 周期性校验 Hash；
- 重连/观战检查点；
- 权威服务器的纠错或违规结果。

Rollback 不是持续发送角色位置，但为恢复、反作弊和观战发送状态仍然合理。

## 客户端职责

每个 Tick：

1. 采样本地输入并发送；
2. 查询远端真实输入；
3. 若未到，使用预测策略；
4. 保存 Tick 前或 Tick 后的可恢复状态；
5. 执行确定性模拟；
6. 记录这一 Tick 实际使用的输入；
7. 渲染当前预测结果。

收到迟到输入：

1. 与当时预测值比较；
2. 找到最早错误 Tick；
3. 恢复该 Tick 前的快照；
4. 重新执行到当前 Tick；
5. 抑制重复副作用；
6. 对画面做短时平滑。

## 服务器职责

Rollback 可以 P2P，但竞技项目常加入服务器：

- 中继输入并隐藏客户端地址；
- 验证输入合法性、频率和顺序；
- 统一决定超时、掉线和已确认 Tick；
- 同时运行权威模拟或抽样审计；
- 处理作弊、结算和回放；
- 向观战/重连客户端提供检查点。

如果服务器也运行模拟，客户端预测结果仍不是最终权威。

## 远端输入如何预测

最常见策略是“沿用上一帧输入”：

```text
上一 Tick：保持向右 + 未按攻击
当前输入未到：继续预测保持向右 + 未按攻击
```

格斗游戏中方向输入连续性较强，但“新按下攻击”难预测。预测策略要倾向于最小化视觉破坏，而不是猜得花哨。

也可以使用：

- No-op；
- 基于移动趋势的有限预测；
- 针对特定动作的游戏规则；
- 本地输入延迟 + Rollback，减少平均回滚深度。

## 状态快照设计

快照必须覆盖所有会影响未来结果的逻辑状态：

- 角色与投射物状态；
- RNG 状态；
- Buff/技能/动画逻辑阶段；
- 定时器和命令队列；
- 实体 ID/generation；
- 碰撞和确定性物理状态。

不应把 GPU 粒子、音频播放句柄和摄像机噪声塞进逻辑快照。

常见实现：

| 方案 | 优点 | 代价 |
|---|---|---|
| 每 Tick 完整快照 | 恢复简单 | 内存和复制成本高 |
| 周期全量 + 中间 Delta | 节省内存 | 恢复链更复杂 |
| Copy-on-Write / 页面快照 | 大状态可能更高效 | 平台和实现复杂 |
| 系统自定义 Save/Load | 可精确控制 | 容易漏字段 |

状态规模和最大回滚窗口决定内存预算：

```text
historyMemory ≈ snapshotSize × rollbackTicks
```

## 副作用不能重复

重模拟会再次执行逻辑，但以下表现不能重复播放：

- 音效；
- 震屏；
- 粒子；
- 成就/埋点；
- 网络请求；
- UI 弹窗。

常见做法：

- 区分 Confirmed Tick 与 Predicted Tick；
- 逻辑事件先写入带唯一 ID 的队列；
- 可撤销表现立即预播，不可撤销副作用等确认；
- 重模拟时只重建逻辑状态，不直接重复外部副作用；
- 对已经展示的事件做去重或补偿。

## 回滚窗口与性能

窗口越大，越能容忍高延迟，但：

- 历史内存增加；
- 单帧重模拟 CPU 峰值增加；
- 视觉修正可能更明显；
- 作弊和延迟玩家影响范围扩大。

超过最大窗口的输入可判定为过期、增加输入延迟、暂停同步或断开连接。不能无限回滚。

## 适用场景

适合：

- 格斗游戏；
- 少人数体育、竞技和高精度动作；
- 状态规模可控；
- 单 Tick 模拟便宜且可确定重放；
- 对本地操作延迟极度敏感。

不适合或成本高：

- MMO/开放世界的巨大状态；
- 数百玩家和大量非确定性物理；
- 每 Tick 模拟本身已经接近预算；
- 副作用和外部系统难以隔离；
- 长距离中途加入和状态快照很重。

# 操作系统、内存与并发模拟面试

## 场景

一场大规模战斗包含数万实体。客户端使用多个 worker 更新移动、技能和可见性，主线程汇总结果。最近出现：

- P99 帧时间从 16 ms 抬升到 40 ms；
- 增加线程后反而更慢；
- 偶现实体已销毁但 Job 仍写入；
- 内存峰值持续上升，重现场景退出后不完全回落。

请先澄清设备、构建、实体规模、任务粒度、复现频率和已有 trace，再开始给方案。

## 第一轮：运行模型

**1. 进程、线程、coroutine 的区别？**
进程隔离地址空间与资源；线程共享进程内存、有独立栈和调度上下文；coroutine 通常由用户态协作调度，不自动并行。追问切换成本、TLS、栈与取消。

**2. 为什么线程越多可能越慢？**
调度与同步开销、工作粒度过小、Cache/TLB 压力、false sharing、内存带宽饱和、主线程汇合成为串行瓶颈。先看 trace，不用“核心数”直接推导线程数。

## 第二轮：内存体系

**3. 虚拟内存解决什么？**
隔离、连续地址视图、按需映射与共享；代价是页表、TLB 和 page fault。不要把虚拟地址等同于常驻物理内存。

**4. 栈、堆为何表现不同？**
栈按作用域移动指针、局部性好；堆需 allocator 元数据、同步和碎片管理。对象最终访问成本取决于布局，不取决于“来自堆”三个字。

**5. 碎片如何分类？**
内部碎片是块内浪费，外部碎片是空闲空间不连续。池化/size class 可缓解特定负载，但会增加保留内存和跨线程回收问题。

## 第三轮：Cache 与布局

**6. AoS 与 SoA 怎么选？**
只批量处理少数字段时 SoA 工作集更小、易 SIMD；经常按实体访问完整对象时 AoS 更直接。用访问模式和目标机数据决定。

**7. false sharing 如何定位？**
线程写不同变量但落在同一 cache line；表现为一致性流量与扩展性差。用硬件计数器/并发 trace 验证，再按线程分片、padding 或批量归并。

**8. 预取为什么不总有效？**
访问不可预测、工作集过大或预取过早/过晚都会失败，还可能挤出有用数据。

## 第四轮：同步正确性

**9. mutex 与 atomic 怎么选？**
复合不变量优先锁；简单计数/状态或经过证明的无锁协议使用 atomic。atomic 只保证指定原子对象和内存序，不自动让整个容器安全。

**10. 死锁如何避免？**
统一锁顺序、缩短临界区、避免嵌套和持锁回调；用超时/锁等待图诊断。能否 try-lock 不是核心，协议是否可证明才是。

**11. 条件变量为什么用 while？**
存在虚假唤醒，且被唤醒到重新获得锁之间条件可能变化；始终在谓词循环中检查。

**12. acquire/release 的意义？**
release 前的写入对读取同一同步变量并成功 acquire 的线程可见；`relaxed` 只保证该原子操作本身，不建立跨对象发布关系。

## 第五轮：Job System

**13. 任务粒度如何决定？**
单任务工作量需显著大于入队、窃取和依赖管理成本；按目标机 trace 调整 batch，并避免长任务拖尾。

**14. 依赖图如何表达？**
声明读写资源与前置 Job，调度器构建 DAG；循环依赖是设计错误。主线程只在真正消费结果前等待。

**15. 如何防止实体销毁后 Job 写入？**
结构变更延迟到同步点；使用 handle + generation；Job 捕获稳定快照/索引而非悬空指针；取消只阻止提交结果，不能假设立即停止底层代码。

**16. 无锁一定更快吗？**
不一定。CAS 重试、缓存行争用、ABA、回收协议和公平性可能更差；低竞争 mutex 常更简单可靠。

## 第六轮：性能与内存增长

**17. 先看哪些指标？**
主/worker 时间线、任务排队与等待、CPU 利用率、Cache miss/带宽、分配速率、常驻/提交内存、对象数和 P95/P99。

**18. 如何区分泄漏与缓存/池保留？**
离开场景后做受控清理并比较可达对象、allocator committed/resident、池容量和 OS 回收行为。RSS 不下降不等于对象仍泄漏。

**19. 如何建立可证伪假设？**
例如“false sharing 导致扩展性下降”，应预测 padding/线程分片后 cache coherence 指标和帧时间改善；只改一个关键变量并回归正确性。

## 最终设计题

为该战斗系统设计数据与调度：

1. 热组件按访问模式拆分连续存储，冷数据分离；
2. 系统声明读写集，按 DAG 分批并行；
3. 每任务处理足够实体，worker 使用本地命令缓冲；
4. 结构变更在帧同步点合并，handle + generation 校验；
5. 主线程只消费稳定快照，渲染读取双缓冲数据；
6. 对分配、队列深度、等待、P99 和对象代数失败做监控；
7. 用确定性回放、TSan/ASan（可用平台）、压力测试和真机 trace 回归。

## 评分

| 层级 | 表现 |
|---|---|
| 0 | 只罗列名词，直接建议“加线程/上无锁” |
| 1 | 能解释机制，但缺少场景和边界 |
| 2 | 能从证据定位瓶颈并给出取舍 |
| 3 | 同时处理正确性、生命周期、观测和回归 |

作答时每题遵循：**结论 → 机制 → 场景证据 → 方案与代价 → 验证**。

# 分游戏类型设计与面试题

## 选型原则

防作弊必须跟随游戏架构。先问：

1. 游戏同步是状态同步、帧同步还是 Rollback？
2. 服务器能否运行完整权威模拟？
3. 客户端必须拥有哪些隐藏信息？
4. 操作频率、玩家数和实体规模多大？
5. 作弊收益来自竞技、经济还是账号？
6. 是否允许交易、UGC、观战、跨平台和模拟器？
7. 玩家对高权限安全组件的接受度如何？
8. 误封一名玩家的业务成本多高？

## FPS / TPS

### 主要作弊

- 自瞄、自动开火、后坐力辅助；
- 透视、ESP 和预瞄隐藏目标；
- 速度、飞行和碰撞异常；
- 命中、射速和弹药伪造；
- 观战窥屏、组队和 Boosting。

### 防线

- 服务器权威移动、射击、弹药和伤害；
- 客户端只提交输入、视角和 Prediction Key；
- Lag Compensation 由服务器在受限历史窗口执行；
- AOI/可见性最小化下发敌方信息；
- 本地预测和服务器校正不影响最终裁决；
- 瞄准/命中时间序列与回放检测；
- 客户端完整性作为辅助证据；
- 举报、观战与人工复核。

只分析命中率会误伤高手；只做客户端扫描无法覆盖外部视觉自动化。

## MMO / 开放世界

### 主要作弊

- 移速、瞬移、穿墙和异常飞行；
- 自动打怪、采集、任务和交易机器人；
- 多开、工作室和资源汇聚；
- 复制物品、重复结算和交易漏洞；
- 客户端脚本、资源和协议滥用。

### 防线

- 服务端移动状态机和空间校验；
- 技能、掉落、任务与资产权威；
- 账本、幂等、事务和资产追踪；
- AOI 减少隐藏信息；
- 在线时长、路径、操作序列和经济图谱；
- 设备/账号/支付/交易多维关联；
- 风险资产冻结、交易限额和延迟到账；
- 对工作室源头、搬运链和销赃节点联合治理。

MMO 的核心往往是“经济反欺诈 + 机器人治理”，不只是战斗外挂。

## RTS / MOBA

### 主要作弊

- 地图全开和读取战争迷雾；
- 自动微操、技能脚本和宏；
- 非法命令、加速 Tick 和不同步；
- 演员、代练、炸鱼和胜负交易；
- 掉线/重连和暂停机制滥用。

### 防线

- 帧输入由服务器排序、限量和校验；
- 服务器同步运行权威模拟或抽样验证 Hash；
- 隐藏信息不下发或按可见范围下发；
- 稳定 Tick、输入日志、检查点和分层 Hash；
- 输入与决策时序检测；
- 匹配、队伍、胜负和设备关系图；
- Replay 复核和赛事裁判工具。

“帧同步”不会自动防止地图信息作弊；客户端若拥有全图状态，就存在读取面。

## 格斗 / 少人数 Rollback

### 主要作弊

- 输入自动化和宏；
- 修改本地确定性逻辑；
- 伪造/延迟输入与网络操纵；
- 状态不同步和结算篡改。

### 防线

- 服务器或 Relay 验证输入顺序、频率和身份；
- 权威服务器可运行同一确定性模拟；
- 输入日志、状态 Hash 和版本校验；
- Rollback 历史与比赛回放；
- 对异常延迟模式和断线策略做公平限制；
- 结算、排名和奖励只由服务器产生；
- 客户端完整性提高逻辑修改成本。

Rollback 解决交互延迟，不等于防作弊协议。

## 卡牌 / 回合制

### 主要作弊

- 读取隐藏牌、随机种子和未来结果；
- 重放、越权和顺序接口滥用；
- 自动决策机器人；
- 胜负交易和多账号互刷；
- 经济与抽卡漏洞。

### 防线

- 隐藏信息和随机结果只在服务器；
- 回合状态机、权限和请求顺序校验；
- Nonce、幂等和事务；
- 棋局/牌局输入日志与可验证回放；
- 对局关系和异常胜负图；
- 机器人风险评分与模式隔离；
- 抽卡、奖励和支付权威账本。

回合制网络流量低，但信息与经济价值高。

## Mobile

额外关注：

- Root/Jailbreak、模拟器、虚拟化和多开；
- 应用重打包、脚本和资源修改；
- 自动点击和设备农场；
- 渠道包、支付和平台账号差异；
- 设备性能导致的安全组件稳定性；
- 隐私、耗电和商店政策。

可结合平台 Attestation、签名和设备风险，但不能将模拟器或 Root 自动等同作弊。低端设备上的性能预算和崩溃影响必须量化。

## UGC / 沙盒

要区分“玩家被允许修改”与“越权修改”：

- UGC 运行在受限脚本环境；
- CPU、内存、网络和文件能力有配额；
- 服务端验证持久化和经济影响；
- 内容签名、审核和版本化；
- Mod 服务器与竞技匹配隔离；
- 私服规则不进入官方排名；
- 防止 UGC 成为任意代码执行和数据窃取入口。

在允许 Mod 的游戏中，防作弊边界应围绕竞技和服务器规则，而不是禁止所有修改。

## 设计题：竞技射击防作弊

回答结构：

```text
资产：公平命中、隐藏位置、排名
-> 权威：服务器模拟移动/命中/伤害
-> 最小信息：按可见性下发
-> 客户端：预测表现 + 完整性风险信号
-> 服务端规则：射速、弹药、移动、回溯窗口
-> 数据检测：瞄准轨迹、可见性、命中上下文
-> 证据：输入日志、快照、回放、版本
-> 处置：阻断、隔离、复核、封禁、申诉
-> 指标：遭遇率、误封率、检测时间、稳定性
```

要主动说明：高水平玩家、手柄辅助瞄准、网络抖动和无障碍工具是误伤边界。

## 设计题：MMO 工作室治理

```text
预防：服务器权威产出、任务和交易
-> 检测：在线/路径/操作 + 设备/账号/交易图
-> 止损：收益递减、交易限额、延迟到账
-> 证据：资产来源与流向账本
-> 处置：冻结链路、隔离账号、追缴
-> 申诉：区分家庭/网吧/合法多账号
```

只封最底层搬砖号会让工作室快速补号；要同时处理资源源头、中转和收款节点。

## 常见错误回答

| 错误 | 缺失 |
|---|---|
| “接一个反作弊 SDK” | 权威架构、玩法校验和运营闭环 |
| “客户端数据都加密” | 解密后仍可观察，服务器仍需验证 |
| “检测到 Root 就封号” | 信号不等于作弊事实，误伤高 |
| “爆头率高就是自瞄” | 缺少上下文、基线和多源证据 |
| “帧同步防作弊差” | 未区分服务器验证、隐藏信息和权威模拟 |
| “所有请求用可靠协议” | 可靠性不等于合法性，还可能队头阻塞 |
| “封禁越多效果越好” | 应看正常玩家遭遇率和误封率 |
| “为了安全可以扫描一切” | 忽略隐私、合规和安全组件自身风险 |

## 2 分钟回答模板

```text
先定义保护资产和主要作弊收益
-> 明确信任边界与服务器权威内容
-> 说明服务器实时阻断的不变量
-> 说明客户端完整性提供的辅助信号
-> 说明行为、关系图、举报和回放如何聚合证据
-> 给出处置梯度、申诉、灰度和隐私边界
-> 用误封、作弊遭遇率和检测时间验证
```

## 项目证据

准备以下指标：

- 非法请求实时拒绝率；
- 正常玩家遭遇作弊的对局比例；
- Precision、Recall 和申诉撤销率；
- 作弊开始到隔离的时间；
- 风险规则/模型版本和 Kill Switch 时间；
- 客户端安全组件 CPU、内存、崩溃影响；
- 工作室资产追缴和复发率；
- 对局回放覆盖和人工审核耗时。

没有实际项目时，也应说明如何用服务器回放、网络模拟、机器人压测、Shadow Mode 和标注集验证方案。

## 最终自测

1. 为什么防作弊首先是服务器架构问题？
2. 透视、自瞄、机器人和经济作弊各自主要证据是什么？
3. 客户端完整性为何只能是分层信号？
4. 哪些动作实时拒绝，哪些需要多局复核？
5. 如何处理 Root、模拟器和共享设备的误伤？
6. 帧同步与状态同步的防作弊重点有什么不同？
7. 如何衡量防作弊系统真正改善了玩家体验？

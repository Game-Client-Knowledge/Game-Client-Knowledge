# 游戏防作弊面试复习

## 核心结论

防作弊不是寻找一个“检测外挂”的万能 SDK，而是围绕游戏资产和公平性建立多层风险控制：

```text
减少客户端知道和决定的内容
-> 服务器验证每次关键状态转移
-> 客户端完整性提高修改成本
-> 行为与关系数据发现未知作弊
-> 证据分级、处置、申诉与持续迭代
```

最重要的信任原则：

> 客户端可以提交输入和请求，可以预测表现，但不能自行决定最终伤害、位置、资源、匹配结果和经济资产。

客户端保护会提高逆向、注入和自动化成本，但不能把玩家设备变成可信服务器。

## 常见作弊分类

| 分类 | 常见表现 | 主要防线 |
|---|---|---|
| 状态修改 | 改生命、速度、冷却、弹药、本地资源 | 服务器权威、状态转移校验 |
| 代码/运行时篡改 | 注入、Hook、修改脚本/资源、绕过逻辑 | 签名、完整性、反篡改、平台证明 |
| 信息作弊 | 透视、地图全开、读取隐藏牌/敌方状态 | 最小化下发、可见性裁剪、行为检测 |
| 输入自动化 | 自瞄、扳机、压枪脚本、宏、机器人 | 服务器约束、输入/行为分析、回放复核 |
| 协议攻击 | 篡改、伪造、重放、加速请求、越权 API | 认证加密、序列/Nonce、幂等、限流 |
| 经济/账号作弊 | 刷资源、重复领奖、盗号、多开、工作室 | 权威账本、事务、设备/账号图谱、风控 |
| 社交与竞技操纵 | 代练、炸鱼、演员、组队串通、胜负交易 | 匹配/关系图分析、举报、回放与处置 |
| 漏洞滥用 | 卡地图、复制物品、异常状态组合 | 服务端不变量、灰度修复、回溯与追缴 |

分类不是互斥的。例如机器人可能同时使用内存读取、自动输入、多账号和经济转移。

## 四层防御

| 层 | 目标 | 代表措施 |
|---|---|---|
| 设计层 | 不把权力和秘密交给客户端 | 服务器权威、最小信息、幂等事务 |
| 客户端层 | 提高篡改成本并产生风险信号 | 代码签名、完整性、模块/环境检测 |
| 服务端层 | 阻止非法结果进入权威状态 | 输入校验、规则模拟、限流、账本 |
| 数据运营层 | 发现未知与低频作弊 | 行为模型、关系图、回放、审核、申诉 |

强防作弊系统依靠这些层互相印证，而不是使用单一信号直接永久封禁。

## 设计问题

对任意作弊问题，按以下顺序分析：

1. **保护什么**：竞技公平、经济资产、隐藏信息还是账号安全？
2. **信任边界**：客户端、服务器、平台和第三方服务各自可信到什么程度？
3. **作弊收益**：攻击者能观察、修改或自动化什么？
4. **预防措施**：能否通过服务器权威或不下发数据直接消除收益？
5. **检测信号**：客户端、服务端、行为和关系数据分别提供什么证据？
6. **处置方式**：拒绝请求、回滚、隔离、延迟封禁还是人工复核？
7. **误伤成本**：信号是否稳定，如何申诉和恢复？
8. **演进能力**：规则、模型、客户端和服务器如何灰度与回滚？

## 30 秒回答

> 游戏防作弊首先依靠架构，而不是客户端扫描。客户端只提交输入和请求，服务器维护权威状态并验证移动、战斗、冷却、资源和事务；敏感信息尽量不下发。客户端签名、完整性与环境检测用于提高修改成本并提供风险信号，服务端再结合行为统计、关系图、回放和举报发现自瞄、机器人、经济与协作作弊。最终处置要依据多源证据分级执行，并提供灰度、申诉、隐私治理和误封监控。

# 行为检测、自动化与数据风控

## 为什么需要行为检测

有些作弊不修改客户端：

- 外部视觉识别配合自动输入；
- 硬件宏和无障碍接口滥用；
- 低强度瞄准辅助；
- 人工工作室和脚本机器人；
- 演员、代练和胜负交易。

它们发送的消息格式完全合法，只能从长期行为、上下文和关系中寻找异常。

## 数据来源

优先使用服务器已知或可验证数据：

| 来源 | 例子 |
|---|---|
| 权威对局事件 | 输入 Tick、视角、开火、命中、移动、技能 |
| 服务器状态 | 距离、可见性、武器、角色状态、延迟 |
| 网络质量 | RTT、Jitter、丢包、校正次数 |
| 客户端风险信号 | 构建完整性、环境和安全组件状态 |
| 账号行为 | 在线时长、模式、设备、登录地点 |
| 经济流水 | 获取、消耗、交易、赠送和退款 |
| 社交/匹配图 | 队友、对手、交易对象、胜负关系 |
| 举报与回放 | 玩家线索、裁判和人工复核 |

客户端上报的遥测也要校验完整性和缺失模式，不能默认诚实。

## 检测层级

### 硬规则

适合逻辑上不可能的行为：

- 未拥有物品却使用；
- 单 Tick 超出合法命令上限；
- 冷却中重复释放；
- 不可见实体被直接操作；
- 事务余额不守恒。

优点：可解释、可直接阻断。

缺点：只能覆盖已知不变量，错误规则会大面积误伤。

### 启发式规则

组合多个弱信号：

- 异常反应时间持续出现；
- 瞄准变化和开火时机高度规律；
- 长时间无休息且路径重复；
- 多账号在相同设备和交易链上协同；
- 胜负模式与对手关系异常。

适合风险评分，不宜用单阈值直接永久封禁。

### 统计与机器学习

模型可识别复杂、缓慢和未知模式，但需要：

- 可信标签和防止标签污染；
- 按段位、武器、角色、输入设备和延迟归一化；
- 训练/验证/线上分布一致；
- 处理概念漂移和版本变更；
- 可解释特征与证据回放；
- Shadow Mode 和灰度评估；
- 模型版本、特征版本与回滚。

模型输出是风险概率，不是法律事实。

## 瞄准辅助检测

可观察高层行为：

- 目标出现到视角响应的时间分布；
- 角速度、角加速度和轨迹平滑性；
- 视角接近目标后的微调模式；
- 开火与准星进入有效区域的关系；
- 不同距离、遮挡和武器下的稳定性；
- 对不可见目标的预跟随；
- 长期命中表现与玩家历史变化。

必须控制混淆因素：

- 鼠标、手柄、触屏和辅助瞄准；
- 高低帧率和网络延迟；
- 武器后坐力与散布；
- 段位、训练模式和职业玩家；
- 观战/回放采样精度。

“爆头率高”或“一次快速甩枪”都不足以证明自瞄。

## 透视与信息作弊检测

服务器首先减少隐藏信息下发。行为侧可关注：

- 对不可见目标的持续预瞄；
- 绕过正常信息获取路径的决策；
- 对随机隐藏事件的异常预测；
- 视角与敌方遮挡状态的长期相关性；
- 团队信息传播是否存在合法来源。

需要结合声音、队友标记、历史暴露、地图知识和技能侦测，否则容易把正常意识判成作弊。

## 机器人与宏

机器人信号通常跨局、跨天：

- 超长在线和固定作息；
- 输入间隔、路径和操作序列高度重复；
- 遇到异常场景时缺乏适应；
- 任务、采集、交易和回城形成稳定模板；
- 多账号共用设备、网络、收款和资源汇聚节点；
- 新账号快速复制相同成长路径。

防御组合：

- 服务端节流与收益递减；
- 高价值操作的风险验证；
- 动态任务和异常场景探针；
- 设备/账号/交易图谱；
- 风险账号进入隔离队列；
- 人机验证只在高风险节点触发；
- 经济源头和销赃链同时治理。

频繁全员验证码会破坏正常体验，也容易被人工打码绕过。

## 举报系统

举报是线索，不是直接证据：

- 按举报者可信度、对局上下文和重复模式加权；
- 防止群体恶意举报；
- 将举报关联到服务器回放和遥测窗口；
- 不向举报者泄露具体检测规则；
- 反馈处置结果时保护被举报者隐私；
- 监控举报到有效证据的转化率。

高水平玩家被举报更多，不能将举报量直接当作作弊概率。

## 回放与复核

用于复核的数据应尽量来自权威输入/状态：

```text
Build/Config Version
+ Match Seed
+ Input/Event Log
+ Server State Checkpoint
+ Network Context
-> 可重放证据
```

视觉录像有助于人工判断，但可能缺少服务器视角、网络修正和隐藏状态。结构化回放更适合定位首次异常。

## 数据质量

检测前检查：

- 遥测是否丢失、重复或乱序；
- 客户端和服务器版本是否匹配；
- 采样率变化是否造成指标突变；
- 新武器/角色是否改变正常分布；
- 机器人是否污染“正常玩家”基线；
- 标签是否来自已确认案件；
- 时区、地区和设备是否产生偏差。

数据管道错误可能比作弊本身制造更多“异常玩家”。

## 评估指标

| 指标 | 说明 |
|---|---|
| Precision | 被判作弊者中真正作弊的比例 |
| Recall | 实际作弊中被发现的比例 |
| False Positive Rate | 正常玩家被误判的比例 |
| Time to Detect | 从作弊开始到发现的时间 |
| Appeal Overturn Rate | 申诉后撤销处罚的比例 |
| Repeat / Evasion Rate | 处置后复发或换号比例 |
| Coverage | 不同模式、地区、设备的覆盖 |
| Player Impact | 作弊者影响的对局和玩家数 |

防作弊不能只追求封禁数量。封得多可能意味着规则误伤，也可能意味着预防层没有阻断。

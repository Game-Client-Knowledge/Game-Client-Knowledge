# 客户端完整性与反篡改

## 定位

客户端保护的作用是：

1. 保证官方分发产物可验证；
2. 提高静态分析和动态修改成本；
3. 发现异常环境与运行时变化；
4. 生成可供服务端风控使用的信号；
5. 延长作弊工具适配新版本的时间。

它不能：

- 让客户端成为最终权威；
- 保证所有作弊都被实时发现；
- 阻止外部设备和视觉输入自动化；
- 单凭一个环境信号安全地永久封禁所有玩家。

## 构建与分发完整性

基础措施：

- 可复现或可追踪的发布构建；
- 二进制、脚本、资源清单和补丁包签名；
- 安全更新链和版本回滚；
- 启动时验证关键清单与依赖；
- 服务器拒绝已撤销或不兼容版本；
- 构建符号、密钥和签名权限隔离；
- CI/CD 与发布账号审计。

只校验主程序不够。动态库、插件、脚本、配置、Shader 和可执行资源同样可能改变逻辑。

## 运行时完整性信号

可关注的高层信号：

- 代码或只读数据段是否与发布清单一致；
- 关键函数入口和调用路径是否异常；
- 非预期模块、驱动或覆盖层；
- 调试、注入、Hook 和进程句柄异常；
- 关键配置、脚本和资源是否被替换；
- 内存保护、页属性和执行区域异常；
- 游戏时钟、系统调用和输入来源异常；
- 安全组件是否按预期启动并持续存活。

这些检测细节和阈值不应写入公开客户端日志或错误消息。服务端只需要稳定的信号 ID、版本、时间和证明上下文。

## 完整性证明

客户端可周期性生成带新鲜度的证明：

```text
Server Challenge / Nonce
+ Client Build / Manifest
+ Platform Attestation
+ Selected Integrity Signals
-> Authenticated Response
```

服务端检查：

- Challenge 是否当前有效；
- 响应是否绑定会话、设备和版本；
- 平台证明是否可信且未重放；
- 信号是否缺失、冲突或长期异常；
- 风险是否足以限制特定能力。

客户端自己生成并自签的“我很安全”没有独立证明价值。密钥若长期静态放在客户端，也只能提高提取成本。

## 平台差异

### PC

开放环境、驱动和覆盖层多，兼容性最复杂。用户态保护侵入较低但可见范围有限；内核级组件观察能力更强，同时带来：

- 系统稳定性和兼容风险；
- 高权限供应链风险；
- 隐私与合规成本；
- 签名、更新和崩溃响应压力；
- 错误可能影响整个操作系统。

使用高权限组件必须有明确必要性、最小权限、独立安全审计和快速停用机制。

### Mobile

可结合应用签名、平台 Attestation、Root/Jailbreak、模拟器、多开框架和 Hook 环境信号。

Root、模拟器或开发者选项不等于作弊事实。它们更适合调整风险等级、限制高价值交易或要求额外验证，而不是不加区分永久封禁。

### Console

封闭平台和认证链降低普通篡改面，但仍需服务器校验、账号风控和漏洞治理。平台安全不能替代游戏逻辑权威。

## 脚本、资源与热更新

脚本化游戏要保护：

- Manifest、脚本和字节码签名；
- 补丁来源、版本、依赖和回滚；
- Loader 只加载授权内容；
- 调试控制台和开发命令在发行包关闭；
- 动态配置不能扩大客户端权威；
- 热更新日志与服务端版本对应。

资源加密主要提高提取门槛。已在客户端解密并使用的数据最终可被观察，敏感服务器逻辑和未揭示结果不应放入包体。

## 混淆与加密

混淆、符号裁剪、控制流保护和字符串加密可以增加分析成本，但代价包括：

- 包体与启动时间；
- 运行时性能；
- 崩溃栈和线上诊断难度；
- 构建复杂度；
- 平台审核和兼容性；
- 攻防适配成本。

应优先保护少量高价值逻辑和安全组件，不把整个客户端变成难以维护的黑盒。

传输加密保护网络中的机密性和完整性；资源加密保护静态提取成本；二者都不阻止已控制客户端在解密后读取数据。

## 环境检测的可靠性

信号可分级：

| 类型 | 例子 | 使用方式 |
|---|---|---|
| 强证明 | 可信平台签名、服务器 Challenge 的有效证明 | 会话准入或高价值能力 |
| 高风险信号 | 多个完整性异常相互印证 | 隔离、加强审计 |
| 弱风险信号 | 模拟器、Root、异常覆盖层 | 评分，不单独封禁 |
| 不稳定信号 | 单次超时、组件崩溃、未知驱动 | 重试、兼容调查 |

任何单一信号都可能受系统更新、安全软件、无障碍工具、直播覆盖层和设备故障影响。

## 对抗更新

客户端规则一经发布就可能被研究。工程上需要：

- 检测规则和信号 ID 可版本化；
- 服务端可灰度启用和调整权重；
- 客户端组件支持快速安全更新；
- 检测逻辑多样化，避免单点绕过；
- 通过 Honeypot/Canary 信号发现异常访问，但不影响正常路径；
- 监控作弊工具适配时间和检测覆盖变化；
- 不在封禁提示中暴露精确触发条件。

不要依赖“隐藏算法”本身。安全性最终来自权威验证和多源证据。

## 隐私与兼容性

客户端检测应遵守：

- 只采集与明确安全目的相关的数据；
- 文档化采集范围、保存周期和访问权限；
- 敏感标识做最小化、脱敏或分级存储；
- 区分安全工具、无障碍软件和作弊工具；
- 提供兼容白名单的审计流程；
- 高权限组件有卸载、更新和故障恢复；
- 地区法规和平台政策评审。

“检测能力更强”不是无限采集的理由。

# 多人游戏调试、测试与可观测性速记

## 先分类现象

| 现象 | 常见方向 |
|---|---|
| 角色抖动/拉回 | 预测分歧、校正、插值缓冲 |
| 远端瞬移 | 快照丢失、外推过久、Tick 跳跃 |
| 幽灵实体 | Spawn/Despawn 乱序、Generation 错误 |
| 重复技能/奖励 | 事件去重、幂等、重连重放 |
| 命中争议 | 时间映射、Lag Compensation、历史状态 |
| 全房间卡顿 | Server Tick、锁、GC、任务拖尾 |
| 单人卡顿 | 网络质量、发送队列、设备帧率 |
| 偶发不同步 | 非确定性、丢输入、版本差异 |
| 无法重连 | Session、检查点、资源版本、槽位过期 |

先区分网络、模拟、表现和业务事务，不要把所有问题归为“延迟”。

## 关联 ID

日志至少携带：

```text
AccountId / PlayerId
ConnectionId / SessionId
MatchId / ServerInstanceId
EntityId + Generation
Packet/Input/Snapshot Sequence
Simulation Tick
Build / Protocol / Config Version
PredictionKey / RequestId
```

没有这些上下文，客户端“Tick 100”与服务器“Tick 100”可能不是同一场比赛。

## 网络模拟

测试矩阵：

- RTT：低、中、高；
- Jitter：稳定与突发；
- Loss：随机和 Burst；
- Reorder、Duplicate；
- 上下行不对称；
- 带宽限制和队列膨胀；
- 网络切换、短断线和长断线；
- 后台/前台恢复；
- NAT/Relay 路径。

所有场景使用可复现 Seed，并记录真实注入参数。

## 确定性与分歧

帧同步/Rollback：

1. 记录开局状态、数据版本和随机种子；
2. 保存排序后的输入日志；
3. 每隔若干 Tick 计算分层 Hash；
4. 二分查找第一个分歧 Tick；
5. 比较 System/Chunk/Entity；
6. 找到第一个不同写入。

常见根因：

- Hash 容器遍历顺序；
- 浮点和数学库；
- 随机调用次数；
- 未初始化内存；
- 并行归并顺序；
- 本地时间或设备输入；
- 脚本/配置版本不一致。

## 状态同步调试

记录：

- 客户端发送的输入；
- 服务器实际消费 Tick；
- 权威快照与 `ackedInputSequence`；
- 客户端预测前后状态；
- 重放输入列表；
- 误差向量和校正方式；
- Snapshot Buffer 和 Render Time。

画出一条时间线通常比只看最终 Transform 更容易定位。

## Packet Capture 与协议日志

- 捕获包头、大小、Channel、Sequence、Tick 和消息类型；
- 敏感令牌和聊天内容脱敏；
- 支持按 Match/Connection 导出；
- 解码工具与协议版本匹配；
- 统计丢包、重传、乱序和队列时延；
- 不在生产长期记录全部高频载荷。

网络抓包说明“发了什么”，服务器 Trace 说明“为什么晚处理”，两者要按时间和 ID 对齐。

## 回放

权威回放可用于：

- 不同步复现；
- 命中和防作弊复核；
- 服务器版本回归；
- 观战和赛事；
- 自动性能场景。

回放格式版本化，并保存必要 Checkpoint。只录视频不能恢复隐藏状态和服务器决策。

## 自动测试

### 单元/属性测试

- 序列号回绕；
- Delta 编解码；
- 幂等和重复事件；
- 状态机非法转移；
- 量化误差边界；
- 输入排序和 Hash。

### 集成测试

- 多客户端加入/离开；
- 丢包和乱序；
- Join Token 过期；
- 重连、Backfill、观战；
- Game Server 崩溃；
- 重复结算；
- 跨版本协议。

### 压力与耐久

- 最大玩家/实体/技能；
- 长时间运行和内存增长；
- 区域故障和批量重连；
- 匹配高峰；
- 最坏网络；
- 机器人持续操作；
- 热更新和滚动发布。

## 服务指标

| 层 | 指标 |
|---|---|
| 接入 | 连接成功、认证延迟、断开原因 |
| 匹配 | Queue P95、质量、取消、分配失败 |
| Game Server | Tick P95/P99、Drift、CPU、内存 |
| 网络 | RTT、Jitter、Loss、Reorder、吞吐 |
| 同步 | 快照/输入频率、校正、回滚、Hash 分歧 |
| 生命周期 | Spawn/Despawn、幽灵对象、重连 |
| 业务 | 对局完成、结算幂等、奖励失败 |
| 安全 | 非法请求、风险对局、误封/申诉 |

## 告警原则

- 同时看客户端体验和服务端资源；
- 按版本、地区、运营商、平台和模式切分；
- 使用分位数，不只看平均值；
- 告警携带最近发布和配置变更；
- 避免单玩家异常触发全局事故；
- 有 Runbook、负责人和回滚入口。

## 事故排查顺序

```text
确认影响范围和版本
-> 判断接入/匹配/游戏服/依赖
-> 对齐 Match、Tick 和网络指标
-> 查最近代码/配置/内容发布
-> 止损：停止分配、降级、回滚
-> 保留回放和证据
-> 修复、回归和复盘
```

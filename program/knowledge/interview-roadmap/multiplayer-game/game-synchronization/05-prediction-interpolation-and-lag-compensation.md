# 预测、插值、校正与延迟补偿

## 这些技术分别解决什么

| 技术 | 作用对象 | 目标 |
|---|---|---|
| 本地预测 | 自己控制的对象 | 隐藏输入到服务器确认的 RTT |
| Reconciliation | 自己控制的对象 | 将预测结果收敛到服务器权威状态 |
| 快照插值 | 远端对象 | 用历史快照平滑抖动和丢包 |
| 有限外推/Dead Reckoning | 远端对象 | 快照短缺时估计短期未来 |
| Rollback | 整个确定性逻辑世界 | 修正错误的输入预测 |
| Lag Compensation | 服务器命中判定 | 按玩家开火时看到的历史场景判定 |
| Visual Smoothing | 渲染表现 | 避免逻辑校正直接产生画面突跳 |

本地预测和远端插值不是同一件事。前者通常走在服务器确认之前，后者通常落后服务器一段时间。

## 本地预测

以角色移动为例：

```text
Tick 120：采样输入 I120
-> 本地 Move(State119, I120) 得到 Predicted120
-> 保存 I120 和 Predicted120
-> 发送 I120
```

预测应尽量复用服务器规则：

- 加速度、速度上限；
- 地面、台阶、斜坡；
- 碰撞和移动模式；
- Buff、负重和输入限制；
- 固定 Tick 与数值规则。

完全复制服务器复杂物理未必可行。可将角色运动设计成可预测的胶囊运动内核，把易分歧的动态交互留给权威校正。

## 服务器校正与输入重放

服务器响应：

```text
MovementCorrection {
  serverTick
  ackedInputSequence
  position
  rotation
  velocity
  movementMode
  supportEntityId?
}
```

客户端：

1. 找到服务器已处理的输入；
2. 比较该时刻预测状态与权威状态；
3. 若误差在容忍范围内，继续预测；
4. 否则将逻辑状态设置为服务器状态；
5. 重放所有未确认输入；
6. 渲染对象从旧画面位置平滑靠近新逻辑位置。

不要只下发位置。没有速度、移动模式、支撑平台或关键 Buff，客户端可能刚校正完就再次分歧。

## 误差策略

按误差大小分级：

| 误差 | 处理 |
|---|---|
| 极小 | 忽略或短时吸收 |
| 中等 | 逻辑立即纠正，画面指数/限速平滑 |
| 很大 | Snap/Teleport，并重置历史与相机 |
| 持续偏差 | 上报诊断，检查规则/数据版本或作弊 |

表现平滑不能改变逻辑碰撞位置，否则会出现“看起来没撞到但服务器判定命中”。可分离 Simulation Transform 与 Render Transform。

## 快照插值

远端对象的快照缓冲：

```text
Server Tick: 200 ---- 201 ---- 202 ---- 203
Render Time:              ^ 在 201 和 202 之间插值
```

常见流程：

1. 估计服务器时间；
2. 将快照按 Tick/Sequence 插入缓冲；
3. 设置 `renderTime = estimatedServerTime - interpolationDelay`；
4. 找到包围 Render Time 的两个快照；
5. 位置线性/三次插值，旋转 Slerp；
6. 事件按 Tick 去重触发。

插值延迟应覆盖常见抖动，而不是固定拍脑袋。可以按到达间隔分布自适应，但变化要平滑，避免时间轴忽快忽慢。

## 外推与 Dead Reckoning

没有未来快照时可短时外推：

```text
predictedPosition = lastPosition + velocity * delta
```

更复杂模型可加入角速度、加速度和移动模式。必须设置：

- 最大外推时间；
- 最大位移/速度；
- 碰撞或导航约束；
- 新快照到达后的平滑校正；
- 失联后的冻结/隐藏策略。

外推适合惯性较强的载具，不适合可瞬间转向、闪现或碰撞密集的角色。

## 服务器延迟补偿

Hitscan 射击中，玩家按下开火时看到的是过去的远端位置。服务器可保存最近一段时间的命中体历史：

```text
客户端上报：inputSequence + shotTick/view + aim
服务器映射到可信历史时间
-> 临时查询该时刻的历史 Hitbox
-> 执行射线判定
-> 恢复当前查询上下文
-> 应用当前时间线的伤害结果
```

关键边界：

- 服务器校准客户端时间，不能直接信任任意时间戳；
- 限制最大回溯窗口；
- 回溯通常只用于查询，不把整个世界永久倒退；
- 校验射速、弹药、视角变化和玩家当时状态；
- 高延迟玩家的补偿不能无限伤害低延迟玩家公平性；
- 投射物与 Hitscan 的补偿模型不同。

## 投射物同步

### Hitscan

客户端立即播放枪口和弹道表现；服务器做回溯射线判定并下发命中结果。网络主要传开火输入、视角、Tick 和结果事件。

### 低速投射物

服务器生成权威投射物，下发 `projectileId + spawnTick + initialState`。客户端可本地预测自己的投射物，并用相同初始状态模拟；服务器在命中或误差过大时纠正。

### 高速或大量投射物

可以只同步生成参数和命中事件，表现层自己飞行；前提是逻辑判定仍在服务器或确定性模拟中。

## 预测事件与去重

客户端预测开火、技能和拾取时，需要稳定的 Prediction Key：

```text
connectionId + inputSequence + actionIndex
```

服务器响应 Accept/Reject/Correct。客户端根据同一 Key：

- 确认已经播放的表现；
- 撤销或补偿被拒绝行为；
- 避免服务器事件再次播放一遍；
- 将临时对象映射到服务器实体 ID。

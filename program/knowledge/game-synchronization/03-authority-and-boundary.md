# 闭环条件与架构边界

## 1. 两个常见误解

学习同步架构时，有两个问题经常被混淆：

- 帧同步是否必须让客户端持有全量数据？
- 服务器跑逻辑，是不是就退回状态同步了？

这两个问题的答案分别涉及**闭环条件**与**架构边界**，本章逐一拆解。

## 2. 帧同步"闭环"的严格条件

帧同步的一致性可以写成归纳：

> 若第 0 帧所有客户端状态相同，且每帧收到相同指令集，且逻辑函数 `f` 确定，
> 则任意帧所有客户端状态相同。

注意：归纳里没有出现"全量数据"。全量数据不是闭环的数学前提，而是工程上
保证下面两条成立的最简单手段：

1. **状态空间一致**：每个客户端持有的"状态"是同一回事（都是整个世界）。
2. **逻辑函数封闭（Self-contained）**：只靠"自己的状态 + 收到的指令"就能
   推进到下一帧，不需要向任何外部者询问。

## 3. 为什么裁剪数据会破坏闭环

一旦做视野裁剪：

- 每个客户端的状态变成"可见子集"，各不相同的状态空间；
- 可见子集的演化通常依赖隐藏部分（视野外的敌人要打你，它的行为是它那条
  指令流驱动的，而它的指令不在你的可见指令集里）；
- 于是逻辑函数在你的子集上不封闭——你没有足够信息推进自己的状态。

结论：**纯帧同步（客户端权威 Lockstep）要自足闭环，客户端必须持有全量
数据。** 裁剪了数据，闭环就裂了，必须有人（服务器）在边界处把缺失的状态
补给你，而"补状态"这件事按定义就是状态同步。所以现实中的"帧同步 + 视野
裁剪"必然是混合架构：内部用 Lockstep，接缝处用状态注入。

## 4. 服务器跑逻辑不等于状态同步

帧同步和状态同步的分界标准是**网络上传输的单元**：

- 帧同步：网络传**输入**（指令），状态是各端自己推出来的，不传；
- 状态同步：网络传**状态**（快照或增量），输入只是客户端到服务器的上报。

"谁跑逻辑"和"传什么"是两个正交的轴：

| | 网络传输入 | 网络传状态 |
| --- | --- | --- |
| **客户端算逻辑** | 经典帧同步（老 RTS） | 罕见，如 P2P 房主权威 |
| **服务器算逻辑** | 服务器权威帧同步 | 经典状态同步（FPS、MMO） |

**服务器权威帧同步**（左下格）是现代 MOBA 的主流实践：服务器也跑同一份
确定性逻辑做裁判，但网络协议依然只转发输入。它保留帧同步的全部通信特性：

- 流量依然极小（还是只传指令）；
- 回放依然免费（存输入流即可重演）；
- 输入延迟模型不变（指令仍然绕服务器一圈）。

它只是放弃了帧同步最初的"省服务器 CPU"红利，换来了反作弊能力。
**通信形态决定它叫帧同步；权威位置只决定可信度与成本。**

## 5. 服务器权威帧同步中的客户端角色

- **经典帧同步**：客户端的本地模拟就是权威（所有客户端互为权威，靠确定性
  保证一致）。
- **服务器权威帧同步**：服务器模拟是权威，客户端模拟只是**渲染副本**。
  客户端照常把指令喂给自己的模拟来出画面，正常时与服务器逐帧一致；一旦
  某客户端篡改逻辑导致分歧，服务器向它推一次状态快照做纠正。

注意："纠正"这个动作本身又是状态同步元素。

## 6. 静默分叉与状态注入

纯 Lockstep 有个著名缺陷：两个客户端一旦分歧，永远不会自己恢复（静默
分叉），因为没有机制告诉任何一方"谁对"。所以哪怕不做视野裁剪，工程上也
会塞进状态哈希对比、定期快照校准这类"状态同步补丁"。

## 7. 光谱总结

从纯输入到纯状态，真实系统都落在中间：

```text
纯客户端帧同步（全量数据，闭环自足，难反作弊）
    | + 状态哈希 / 快照校准（防静默分叉）
    | + 服务器跑裁判逻辑（服务器权威帧同步，仍是传输入）
    | + 视野裁剪（边界处必须注入状态，混合架构）
    v
纯状态同步（服务器算、传状态，天然权威）
```

两个问题的答案：

1. **"不跑全量数据，帧同步无法闭环？"**
   对纯帧同步而言是的。闭环靠"相同状态 + 相同输入 + 确定性"，全量数据是
   让客户端状态空间彼此一致、逻辑自足的最简单方式；一旦裁剪，必须在接缝
   处用状态注入补全，机制就不再是纯帧同步。
2. **"服务器跑逻辑就退回状态同步？"**
   不是。退不退看网络上传什么：只要还是只传输入、状态不传，就仍是帧同步
   （服务器权威帧同步）。只有当服务器开始推送状态（纠正、补视野、快照）
   时，才是掺入了状态同步——而现代系统几乎全都掺了一点。

一句话：**"帧同步 / 状态同步"刻画的是网络协议，不是计算位置；"客户端算 /
服务器算"刻画的是权威与可信度。两者正交，混合才是常态。**
